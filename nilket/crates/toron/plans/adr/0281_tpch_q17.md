# ADR 281 — tpch.q17 reachability attempt (correlated scalar subquery)

## Status
Proposed.

## Context
The gauge has seven reach cells dev+strict green (q01/q03/q04/q05/q06/q10/q14) and three correctness cells
(q06/q01/q03). Per the operator's steer, the next *reach* ADR lets a remaining **hard class** nominate itself
rather than re-measuring an already-green shape. Grounding the frontend confirmed most forward-arc candidates
are **already supported** — global aggregate scalar subqueries (ADR 257), bare correlated aggregate scalar
subqueries (ADR 260), IN/NOT-IN incl. correlated (256/258/259), `EXTRACT` (q07/08/09), `COUNT(DISTINCT)` (q16),
and `CASE`-in-aggregate (q14 runs `SUM(CASE …)`). The decorrelation arc stands at: correlated EXISTS ✓
(pre-256, plus 279 for unqualified refs), correlated IN ✓ (259), bare correlated aggregate scalar ✓ (260). The
gap q17 targets is the next scalar form: an unqualified outer reference inside a scalar subquery whose
projection wraps the aggregate in arithmetic (`0.2 * AVG(...)`) instead of projecting one bare aggregate.

**tpch.q17** (Small-Quantity-Order Revenue) is the cleanest probe of that scalar wall: its predicate carries a
**correlated** scalar subquery, and it joins only **part ⋈ lineitem** — both already in the harness, so no new
table (q02 hits related scalar territory but drags in `partsupp`; defer it). A reachability attempt in the
269/272/274/277/278 mold: bring q17 in, run dev + strict, record the first wall; implement no wall.

q17 shape (tpchgen-2.0.2's exact Q17, `:1` → `'Brand#23'`, `:2` → `'MED BOX'`, no LIMIT):
```sql
SELECT SUM(l_extendedprice) / 7.0 AS avg_yearly
FROM lineitem, part
WHERE p_partkey = l_partkey AND p_brand = 'Brand#23' AND p_container = 'MED BOX'
  AND l_quantity < (SELECT 0.2 * AVG(l_quantity) FROM lineitem WHERE l_partkey = p_partkey)
```

## The expected first wall (verify-first — the impl measures plan + bind + execute)
The correlated scalar subquery `(SELECT 0.2 * AVG(l_quantity) FROM lineitem WHERE l_partkey = p_partkey)`
references the outer `p_partkey`, but the official text is unqualified (`l_partkey = p_partkey`). That creates
two plausible, adjacent walls and the implementation must measure which one is first:

1. The scalar path may fail to recognize the unqualified outer ref and bind the subquery as if `p_partkey`
   belonged to the inner `lineitem`, producing an unresolved-column bind wall.
2. If/when the correlation is recognized, ADR 260 still only accepts a **bare** aggregate projection; q17's
   `0.2 * AVG(l_quantity)` wrapper should reject as the deferred wrapped-correlated-aggregate scalar form.

Both are the same frontier family — binder-resolved correlated scalar decorrelation beyond ADR 260's bare
aggregate case — but the row, phase, classifier, and next ADR name follow the measurement (the q04 → ADR 279
pattern). **If q17 unexpectedly passes**, that is itself a useful result — the gauge gains its first
correlated-scalar cell and we pivot to the next measured row. Everything else is already exercised by green
queries: `SUM` + scalar divide, the `p_brand`/`p_container` equality filters, and the `part ⋈ lineitem` comma
join.

## Decision
Bring q17 into the gauge as a measured row in **both** modes; implement no wall.

1. **q17 SQL, tpchgen-exact first.** `:1` → `'Brand#23'`, `:2` → `'MED BOX'`, no LIMIT. Keep the official
   unqualified `l_partkey = p_partkey` predicate; do not qualify it to dodge the first wall. Start with the
   same exact text in both modes. If strict walls only on harness literal typing (`7.0` / `0.2`) before the
   intended scalar-correlation wall, introduce the narrow strict literal variant the measured error requires
   and record the deviation in the results doc.
2. **Fixtures (append-only — no new table).** Append `p_brand` + `p_container` (Utf8) to the `part` fixture
   (today `p_partkey`/`p_type`); confirm the `lineitem` fixtures expose `l_quantity` + `l_extendedprice` (the
   q01/q06 money columns) and `l_partkey` (present, q14) — append only what q17 needs and existing queries lack.
   Existing queries reference none of the new columns, so their outputs/digests + the q06/q01/q03 correctness
   cells stay stable.
3. **Wire + measure precisely (ADR 262).** `run_dev_q17` / `run_strict_q17`, CLI `--query q17`, `status_rows` →
   q17 `implemented`. Run both modes; honest row — `pass`, a **specific** recognized blocker named *after* the
   probe reports it, or an honest `fail`. The measured first wall names the next ADR; classify it precisely, not
   under a generic bucket.

## Watch-items (operator) → guards
- **Empirical Phase 0, no overfit.** The first wall may be unqualified outer-ref resolution or wrapped
  correlated-aggregate projection; the row, classifier string, and next-ADR name are set from the gauge's
  actual output, not pre-baked.
- **Pivot if it passes.** A `pass` is a real outcome (first correlated-scalar cell); do not force a wall.
- **Append-only fixtures.** New `part` columns appended at the end; the seven reach cells + q06/q01/q03
  correctness stay unchanged (verify existing tests green).
- **No engine feature.** Nothing added to force q17 through; the measured wall names the next ADR.
- **`status` stays static inventory** (q17 → `implemented`); the measured row lives only in the matrix.
- **Test stack.** q17 is a 2-relation join + a subquery — try a bare `#[tokio::test]` first; fall back to the
  explicit `std::thread::Builder` stack-size wrapper if the future overflows libtest's default stack.

## Acceptance
- q17 moves `not_run` → a measured row (pass | specific recognized blocker | honest fail) in both modes; the
  reachability matrix + a harness test render it.
- If blocked, the reason is allowlisted with a precise classifier (named from the measured message) and names
  the next ADR (the measured correlated-scalar cut, not a guessed generic bucket).
- q01/q03/q04/q05/q06/q10/q14 reachability + the q06/q01/q03 correctness cells are unchanged.

## Forward arc
The measured wall decides: an unqualified outer-ref wall → binder-resolved scalar-correlation handoff; a
wrapped-aggregate wall → generalized correlated aggregate scalar projection beyond ADR 260's bare aggregate; a
`pass` → the first correlated-scalar reach cell, pivoting to the next measured row. q05 correctness stays
available on the rail, independent of this.

The `toron-tpch` reachability gauge + whatever frontend/binder wall q17 surfaces. No cross-ring surface.
