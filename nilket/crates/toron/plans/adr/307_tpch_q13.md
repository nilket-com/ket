# ADR 307 — tpch.q13 reachability

## Status
Proposed.

## Context

Reach frontier reopens after boards-level 15/15. q13 is a meaty join-frontier machete — its first wall is the
**non-equi outer-join `ON` predicate** (a confirmed lowering reject), with a count-of-counts behind it. A
**verify-first reach probe**: add q13, measure the first wall, classify precisely, name the engine ADR.

```sql
SELECT c_count, COUNT(*) AS custdist
FROM (
  SELECT c_custkey, COUNT(o_orderkey) AS c_count
  FROM customer LEFT OUTER JOIN orders
    ON c_custkey = o_custkey AND o_comment NOT LIKE '%special%requests%'
  GROUP BY c_custkey
) AS c_orders
GROUP BY c_count ORDER BY custdist DESC, c_count DESC
```

## Grounded walls (in order)
1. **Non-equi outer-join `ON` predicate** — `o_comment NOT LIKE '%special%requests%'` lives in the `LEFT OUTER ON`
   (it *cannot* move to WHERE on an outer join — it controls which orders match → which customers null-extend).
   `lower_join_operator` accepts the `ON` constraint, then `lower_join_on` recursively extracts equality conjuncts
   and rejects the `NOT LIKE` residual with `"join ON only supports equality predicates"`. **The expected first
   wall.**
2. **count-of-counts** — outer `GROUP BY c_count` where `c_count = COUNT(o_orderkey)` (group by a derived
   aggregate). Behind wall 1.
3. `COUNT(o_orderkey)` non-null semantics (LEFT OUTER no-match → null → 0); the multi-wildcard `NOT LIKE
   '%special%requests%'`. Behind walls 1-2.

## Decision

Add q13 dev+strict, official shape, `STRICT_Q13_SQL = Q13_DEV_SQL`. **Verify-first** — harness-only; measure the
first wall, don't solve it.

### D1 — fixtures: none (measure-first; the wall precedes column-resolution)
The non-equi-`ON` reject is in **frontend lowering** (`lower_join_operator`), which runs **before** the binder
resolves columns — q22's SUBSTRING wall (`@plan`) already proved lowering rejects fire before binding. So q13
should hit the non-equi-`ON` wall **regardless of `o_comment`**, and the orders fixture (which lacks `o_comment`)
needs **no change** for this reach probe. Wire q13 over the existing `customer` + `orders` fixtures.
- **Contingency only:** if Phase-0 shows q13 hits a column-resolution wall (`o_comment` not found) *before* the
  non-equi-`ON`, then add `o_comment` (Utf8, from `OrderGenerator`) so the real wall surfaces — and verify no
  regression on the shared orders fixture (q03/q04/q12/q18/q22 + goldens). Expected: not needed. **`o_comment` is
  otherwise deferred** to the future q13 correctness cut (when q13 executes and needs real `%special%requests%`
  data).

### D2 — wiring
`Q13_DEV_SQL`/`STRICT_Q13_SQL`; `q13_tables` (customer + orders, existing fixtures); `run_dev_q13`/`run_strict_q13`;
`status_rows`; `main.rs` routes `"q13"`; matrix row.

### Verify-first — measure + classify precisely
Run q13 at sf=0.01; record the measured row. Expected: **`blocked(<non-equi-join-on>@plan)`** in both modes.
- **Classify it precisely** — add a specific telemetry reason matching the measured `"join ON only supports
  equality predicates"` reject (e.g. `unsupported_non_equi_join_on`), placed before the generic buckets; no
  overclassification. If the raw reject differs, record it raw (don't force a broad classifier).
- **Do not solve** the non-equi-`ON` predicate, the count-of-counts, the `COUNT`-non-null, or the multi-wildcard
  `NOT LIKE` — deferred behind the first wall (later ADRs).

## Acceptance
- `q13 dev`/`strict` record a **precise** measured row at sf=0.01 — expected the non-equi outer-join `ON` wall (or
  another precise wall). Reach + correctness rows unchanged (q13 stays red).
- A harness test pins the measured row + reason; `matrix` includes q13. Documented in
  `crates/toron/plans/impl/307_tpch_q13_results.md`.
- **No fixture change** (unless the Phase-0 contingency fires) → q03/q04/q12/q18/q22 + the 15/15 boards unchanged.

## Boundaries
- Reachability only; no q13 correctness oracle. No engine work (the non-equi-`ON` is ADR 308). No fixture change
  expected; classifier must be specific.

## Forward arc
**ADR 308 = non-equi outer-join `ON` predicate** — the meatiest remaining join-semantics cut (an `ON`-clause filter
that can't move to WHERE on an outer join). Then q13 re-measures (count-of-counts → ADR 309+); the `o_comment`
fixture rides the future q13 correctness cut. q19 (disjunctive) remains the other big machete.

## Why toron-home / harness
A `toron-tpch` reachability addition (query + wiring + a precise classifier); no `crates/toron` engine change, no
fixture change expected, no Wendelon / cross-ring surface.
