# ADR 317 — tpch.q21 reachability

## Status
Proposed.

## Context

q21 reach, **verify-first, measure-first** — the **last probe; it closes the failure atlas**. q21 is one of the
hardest remaining TPC-H shapes in the harness: a triple `lineitem` self-join (l1/l2/l3) via a correlated `EXISTS`
*and* a correlated `NOT EXISTS`, each carrying a `<>` cross-side correlation. Measure the first wall rather than
predicting it.

```sql
SELECT s_name, COUNT(*) AS numwait
FROM supplier, lineitem l1, orders, nation
WHERE s_suppkey = l1.l_suppkey AND o_orderkey = l1.l_orderkey AND o_orderstatus = 'F'
  AND l1.l_receiptdate > l1.l_commitdate
  AND EXISTS (SELECT * FROM lineitem l2
              WHERE l2.l_orderkey = l1.l_orderkey AND l2.l_suppkey <> l1.l_suppkey)
  AND NOT EXISTS (SELECT * FROM lineitem l3
                  WHERE l3.l_orderkey = l1.l_orderkey AND l3.l_suppkey <> l1.l_suppkey
                    AND l3.l_receiptdate > l3.l_commitdate)
  AND s_nationkey = n_nationkey AND n_name = 'SAUDI ARABIA'
GROUP BY s_name ORDER BY numwait DESC, s_name LIMIT 100
```

## Grounded candidate walls / gaps (measure the order)
1. **Correlated EXISTS / NOT EXISTS with a `<>` cross-side correlation — the engine question.** The current EXISTS
   classifier maps correlated **equi**-pairs (`sub.b = outer.a`) → `l2.l_orderkey = l1.l_orderkey`
   decorrelates fine, but `l2.l_suppkey <> l1.l_suppkey` is a **non-equi cross-side correlation** that likely won't
   decorrelate/bind onto the membership key. Probable first engine wall — a **new family** (correlated non-equi
   correlation in EXISTS/NOT EXISTS). The EXISTS bodies are **not grouped**, so this is *not* q18's
   grouped-membership-body wall.
2. **Fixture gap — `o_orderstatus` absent** (q21 filters `o_orderstatus = 'F'`). `l_receiptdate`/`l_commitdate`/
   `l_suppkey`/`l_orderkey`/`s_name`/`s_suppkey`/`s_nationkey`/`n_name`/`o_orderkey` all exist. **Measure-first:**
   add `o_orderstatus` only if column-resolution masks the deeper wall (the q13/q18/q19 contingency).
3. Supported: the non-equi *filter* `l1.l_receiptdate > l1.l_commitdate` (column-vs-column dates, q12); the 4-table
   base join; `o_orderstatus`/`n_name` literals; `<>` as a plain comparison; `GROUP BY s_name` + `COUNT(*)`;
   2-key ORDER BY; `LIMIT 100` (`Take`/`Sort.limit`, q18 correction). The triple self-join has no guard — likely OK
   structurally; the `<>` correlation is the risk, not the aliasing.

## Decision

Add q21 dev+strict, official shape, `:1` nation = `'SAUDI ARABIA'`, `LIMIT 100`, `STRICT_Q21_SQL = Q21_DEV_SQL`.
**Verify-first, measure-first** — classify only the measured wall; no speculative fixtures unless the contingency
proves needed. **Mode-agnostic** (output `s_name` Utf8 + `numwait` Int64, no decimals → dev==strict digest).

### D1 — fixtures: none up front (`o_orderstatus` is the contingency)
`q21_tables(strict, sf)` over `supplier` + `lineitem` + `orders` + `nation` (existing fixtures). **Contingency:**
if the measured wall is `o_orderstatus` not-found `@bind` *before* the correlated-`<>` wall, add `o_orderstatus`
(Utf8, from `OrderGenerator`) + verify no regression on the shared orders fixture (q03/q04/q05/q10/q12/q13/q22 +
goldens). Re-measure after.

### D2 — wiring
`Q21_DEV_SQL`/`STRICT_Q21_SQL`; `q21_tables`; `run_dev_q21`/`run_strict_q21`; `status_rows`; `main.rs` routes
`"q21"`; matrix row.

### Verify-first — measure
Run q21 at sf=0.01 both modes; record the rows. **No predicted outcome.** Classify the measured wall **precisely**
(reuse an existing reason only if it matches *and* the cause is confirmed; else a precise new reason or documented
`fail(unrecognized@phase)`). If it reaches a join shape, keyed check (ADR 311 habit — the triple self-join must not
be a fake-green cartesian). No pre-solve.

## Acceptance
- q21 dev/strict record **honest** measured rows at sf=0.01. q21 counts as keyed-green reach only if both modes
  `pass@execute` (keyed). Prior reach rows and correctness rows remain unchanged. Fixture change only on the
  contingency.
- `matrix` includes q21; a harness test pins the measured rows. Results doc records: which wall fired first
  (`o_orderstatus` gap vs correlated-`<>` EXISTS/NOT-EXISTS vs other), the raw reject, the next-ADR direction —
  **plus the completed atlas**.

## Boundaries
- Reachability only; no q21 correctness oracle. No engine work in this cut. The correlated-`<>` wall (if measured)
  defers to its own engine ADR.

## Forward arc — the atlas is complete
q21 is the **last reach probe**. After it, the remaining reach work is a closed, named set of wall families with
measured reproductions:
- **q11** — scalar subquery in HAVING
- **q15** — keyless-cross (composite/aggregate build side)
- **q18** — grouped membership-subquery body
- **q19** — keyless-cross (disjunction hides the equi-key) *(same family as q15)*
- **q21** — likely correlated non-equi (`<>`) correlation in EXISTS/NOT EXISTS *(this cut measures it)*

Then the engine sequence is fully scoped: each ADR can name **all the rows it should move**. q15+q19 are now a
candidate shared keyless-cross family, with the matrix + keyed-plan habit catching intended flips *and* fake-green
cartesians. The fog bank becomes a work plan.

## Why toron-tpch / harness
A `toron-tpch` reachability addition (query + wiring; fixture add only on the contingency); no `crates/toron`
engine change in this cut. The correlated-`<>` cut (if measured) is a separate engine ADR. No Wendelon /
cross-ring surface.

## Grounding evidence
The latest drafts converge on verify-first q21 reachability and the same two concrete candidate walls: the
correlated `<>` cross-side predicate, and the `o_orderstatus` fixture contingency. The code read supports both:
the EXISTS classifier is equi-correlation plus inner-residual shaped; `orders_schema` does not yet include
`o_orderstatus`; q21's EXISTS bodies are not grouped (unlike q18); the date filter and `LIMIT` surfaces are already
exercised elsewhere; and the projected output is mode-agnostic. q21 closes the failure atlas. Measure, don't
predict.
