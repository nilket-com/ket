# ADR 290 — tpch.q12 reachability

## Status
Proposed.

## Context

Three correctness cuts in a row (q05/q17/q14) — this is a reach breather. Board: 10 reach (q01-06, q10, q14,
q17, q20), 6 correctness. q12 is the cleanest next reach probe: a small two-table comma join exercising a
different slice of the **already-built** surface — not an engine cut by assumption. The SQL is tpchgen Q12 with
`:1`/`:2`/`:3` bound to `'MAIL'`/`'SHIP'`/`DATE '1994-01-01'`; only the interval upper bound is literalized.

```sql
SELECT l_shipmode,
  SUM(CASE WHEN o_orderpriority = '1-URGENT' OR o_orderpriority = '2-HIGH' THEN 1 ELSE 0 END) AS high_line_count,
  SUM(CASE WHEN o_orderpriority <> '1-URGENT' AND o_orderpriority <> '2-HIGH' THEN 1 ELSE 0 END) AS low_line_count
FROM orders, lineitem
WHERE o_orderkey = l_orderkey AND l_shipmode IN ('MAIL', 'SHIP')
  AND l_commitdate < l_receiptdate AND l_shipdate < l_commitdate
  AND l_receiptdate >= DATE '1994-01-01' AND l_receiptdate < DATE '1995-01-01'
GROUP BY l_shipmode ORDER BY l_shipmode
```

It probes: the `orders ⋈ lineitem` comma join (keyed by ADR 270's recognizer), string `IN` over `l_shipmode`,
`SUM(CASE … THEN 1 ELSE 0)` count-style aggregates with `OR`/`<>`/`AND` predicates inside the branches, and
Date32 **column-to-column** inequalities (`l_commitdate < l_receiptdate`, `l_shipdate < l_commitdate`) plus a
literal date range. Grounding says these are all landed primitives, so the expected outcome is `pass@execute` —
but this is **verify-first**, not an acceptance shortcut.

## Decision

Add q12 to the reachability harness in dev and strict modes, official-shaped with parameters inlined and the
upper date bound **literalized**. This is harness-only **unless** the verify-first run measures a real wall.

### D1 — fixture (append-only)
Append `l_shipmode` (Utf8, non-nullable) to the dev and strict `lineitem` schemas + generators (tpchgen exposes
`item.l_shipmode`; push `item.l_shipmode.to_string()`), like ADR 285's `p_name`. `orders` already carries
`o_orderpriority`/`o_orderkey`; `lineitem` already carries `l_shipdate`/`l_commitdate`/`l_receiptdate`/`l_orderkey`.
**`l_shipmode` is q12's only new data surface.** The append-only rule is load-bearing: existing q01/q03/q05/q06/
q10/q14/q17/q20 reach rows and all correctness cells must not move — the gate proves it.

### D2 — wiring
`Q12_DEV_SQL` / `STRICT_Q12_SQL` (identical text; q12 references only shared key/date/string columns and integer
CASE literals, while the mode-specific Decimal columns are unused); `q12_tables(strict, sf)` over `orders` +
`lineitem`; `run_dev_q12` / `run_strict_q12`; `status_rows` "implemented" entry; `main.rs` routes `"q12"`; matrix
row. `facts_for_batch` on both tables.

### Verify-first — measure, don't assume
Run q12 after wiring and record the **measured** row at the **default reachability scale (`sf=0.01`)**:
- pass@execute in both modes → the board becomes **11** reach cells; **and the comma join must be keyed at
  default scale** — a tiny-scale pass alone is not evidence (the q14/q17 cartesian lessons).
- a block/fail → the row stays red with the **precise** measured phase + reason, which names ADR 291. **No broad
  classifier** to make a generic error look recognized — leave it unrecognized unless the message is specific
  enough not to mask unrelated bugs.

## Boundaries
- **No q12 correctness oracle** (reachability only); `correctness.jsonl` / `correctness-matrix` unchanged.
- No Date32+interval runtime kernel (bounds literalized).
- No engine work unless the verify-first run measures a real wall (then it's ADR 291, not smuggled here).
- **Don't guess the count-aggregate output type** — it only matters for a future q12 correctness oracle.
- Append-only fixture; no answer-set / sort-policy decisions.

## Acceptance
- `run --query q12 --mode dev` and `--mode strict` record `pass@execute` at `sf=0.01` (comma join keyed), **or** a
  precise measured red row naming ADR 291.
- `matrix` includes q12; existing reach rows unchanged, and the correctness test rail remains green with the
  appended `lineitem` column.
- Documented in `crates/toron/plans/impl/0290_tpch_q12_results.md`.

## Forward arc
If green: reach → 11, and q12 is a strong correctness-catchup candidate (two grouped integer counts,
deterministic `ORDER BY l_shipmode`, no Decimal division — a new oracle shape). If it walls: that wall names
ADR 291.

## Why toron-home / harness
A `toron-tpch` reachability addition (fixture column + query + wiring); no `crates/toron` engine change expected,
no Wendelon / cross-ring surface. (If the verify-first run finds a wall, the engine ADR 291 it names is scoped
separately.)

## Council provenance
3/3 on q12 (Claude/Antigravity/Codex). The engine-frontier alternative (q07 nation self-join) was the surfaced
fork; the room chose the clean coverage cut that sets up the correctness catchup. Disciplines folded: verify-first
at default scale (keyed comma join, not tiny-scale — q14/q17 lesson); no broad classifier; append-only; defer the
count output type to a future oracle.
