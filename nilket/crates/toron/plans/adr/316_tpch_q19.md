# ADR 316 — tpch.q19 reachability

## Status
Proposed.

## Context

q19 reach, **verify-first, measure-first** — one of the last two probes that complete the reach map. The project is
moving from query-support-by-intuition to a **failure atlas**: named wall families with measured reproductions.
q19's value is diagnostic — its disjunctive predicate may hit the **same keyless-cross/broadcast-build-side reject
as q15** (different cause), telling us the wall is a *family*, not a one-off. **No prediction** (reach calls
0-for-3: q15, q11, q18 all overturned by measurement).

```sql
SELECT SUM(l_extendedprice * (1 - l_discount)) AS revenue
FROM lineitem, part
WHERE (p_partkey = l_partkey AND p_brand = 'Brand#12' AND p_container IN ('SM CASE','SM BOX','SM PACK','SM PKG')
       AND l_quantity >= 1  AND l_quantity <= 11 AND p_size BETWEEN 1 AND 5
       AND l_shipmode IN ('AIR','AIR REG') AND l_shipinstruct = 'DELIVER IN PERSON')
   OR (p_partkey = l_partkey AND p_brand = 'Brand#23' AND p_container IN ('MED BAG','MED BOX','MED PKG','MED PACK')
       AND l_quantity >= 10 AND l_quantity <= 20 AND p_size BETWEEN 1 AND 10
       AND l_shipmode IN ('AIR','AIR REG') AND l_shipinstruct = 'DELIVER IN PERSON')
   OR (p_partkey = l_partkey AND p_brand = 'Brand#34' AND p_container IN ('LG CASE','LG BOX','LG PACK','LG PKG')
       AND l_quantity >= 20 AND l_quantity <= 30 AND p_size BETWEEN 1 AND 15
       AND l_shipmode IN ('AIR','AIR REG') AND l_shipinstruct = 'DELIVER IN PERSON')
```

## Grounded candidate walls / gaps (measure the order)
1. **The disjunctive predicate (OR-of-ANDs) — the engine question.** The equi-key `p_partkey = l_partkey` is
   buried *inside* each OR-branch; `recognize_cross_equi_joins` splits on **AND** via
   `split_logical_and_conjuncts`, so a top-level OR is one opaque conjunct → the key isn't recognized → keyless
   `lineitem × part` Cross. **Likely the `unsupported_cross_join`/broadcast-build-side reject** — same message as
   q15, **different cause** (disjunction hides the key, vs q15's composite build side).
2. **Fixture gap — `l_shipinstruct` absent** (every branch filters `l_shipinstruct = 'DELIVER IN PERSON'`).
   `p_container`/`l_shipmode`/`p_size`/`l_quantity`/`p_brand`/`p_partkey`/`l_partkey`/`l_extendedprice`/`l_discount`
   all exist. **Measure-first:** the disjunctive keyless-cross and `l_shipinstruct` resolution are both `@bind`, so
   the order is uncertain — add `l_shipinstruct` only if column-resolution masks the disjunctive wall.
3. Supported: `IN`-lists, `BETWEEN`, range (`>= … <=`), the discounted-revenue global `SUM` (q01/q06).

## Decision

Add q19 dev+strict, official shape (3 OR-branches inlined), `STRICT_Q19_SQL = Q19_DEV_SQL`. **Verify-first,
measure-first** — classify only the measured wall; no speculative fixtures unless the contingency proves needed,
and treat `unsupported_cross_join` as *evidence only after confirming the cause*. **Not mode-agnostic** (`revenue`
Decimal/Float64); single global SUM → one output row.

### D1 — fixtures: none up front (`l_shipinstruct` is the contingency)
`q19_tables(strict, sf)` over `lineitem` + `part` (existing fixtures). **Contingency:** if the measured wall is
`l_shipinstruct` not-found `@bind` *before* the disjunctive keyless-cross, add `l_shipinstruct` (Utf8, from
`LineItemGenerator`) + verify no regression on the shared lineitem fixture (the many lineitem-backed rows +
goldens). Then re-measure to reach the disjunctive wall.

### D2 — wiring
`Q19_DEV_SQL`/`STRICT_Q19_SQL`; `q19_tables`; `run_dev_q19`/`run_strict_q19`; `status_rows`; `main.rs` routes
`"q19"`; matrix row.

### Verify-first — measure
Run q19 at sf=0.01 both modes; record the rows. **No predicted outcome.** Classify the measured wall **precisely**;
if it's the keyless-cross, reuse q15's `unsupported_cross_join` reject **only after confirming the disjunctive
cause** — and record the cause + the q15 match (family evidence). No pre-solve.

## Acceptance
- q19 dev/strict record **honest** measured rows at sf=0.01. q19 counts as keyed-green reach only if both modes
  `pass@execute` at the default scale with tractable elapsed time (the anti-cartesian check). Prior reach +
  correctness rows stay unchanged. Fixture change only on the contingency.
- `matrix` includes q19; a harness test pins the measured rows. Results doc records: which wall fired first
  (`l_shipinstruct` gap vs disjunctive keyless-cross), whether it **matches q15's `unsupported_cross_join`** (after
  cause confirmation), and the next-ADR direction.

## Boundaries
- Reachability only; no q19 correctness oracle. No engine work in this cut. The disjunctive predicate defers to its
  own engine ADR (factor the common equi-key out of the OR-branches).

## Forward arc — the failure atlas
q19 + q21 are the last reach probes. Once measured, the remaining reach work stops being a fog bank and becomes a
**small set of named wall families with measured reproductions**:
- **q11** — scalar subquery in HAVING
- **q15** — keying a join against a composite/aggregate (CTE) input
- **q18** — grouped membership-subquery body (gates q18's eventual composite-join question)
- **q19** — disjunction hiding join keys (this cut) [+ possible `l_shipinstruct` fixture gap]
- **q21** — still unknown (next probe)

That atlas is when engine cuts get much less speculative: one ADR is scoped by **all the rows it should move**, and
the matrix catches both the intended flips *and* any fake-green cartesian (the ADR 311 keyed-plan habit). If q19's
keyless-cross matches q15's, the keyless-cross is a *family* (composite + disjunction): one inventory, with
cause-specific fixes.

## Why toron-home / harness
A `toron-tpch` reachability addition (query + wiring; fixture add only on the contingency); no `crates/toron`
engine change in this cut. The disjunctive-predicate cut is a separate engine ADR. No Wendelon / cross-ring surface.

## Council provenance
Operator + Claude, verify-first. Operator endorsed the framing: no speculative fixture; measure the first wall; add
`l_shipinstruct` only if column-resolution masks the real predicate/join issue; treat `unsupported_cross_join` as
evidence *only after confirming the cause* (keeps the row honest). The failure-atlas framing — separating named
wall families with measured reproductions — is the strategic frame for the engine batch after q21. 0-for-3 →
measure, don't predict.
