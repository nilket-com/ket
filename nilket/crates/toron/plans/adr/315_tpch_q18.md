# ADR 315 — tpch.q18 reachability

## Status
Proposed.

## Context

q18 reach, **verify-first, measure-first** — narrow and honest. Its value is diagnostic, not just another row:
q18's `IN (grouped aggregate)` may share q15's composite-input-join wall, so measuring it tells us whether q15's
wall is isolated or part of a broader composite-join problem. **No prediction** (reach calls are 0-for-2: q15, q11
both overturned by measurement); static grounding may name likely walls, but the live row still decides.

```sql
SELECT c_name, c_custkey, o_orderkey, o_orderdate, o_totalprice, SUM(l_quantity)
FROM customer, orders, lineitem
WHERE o_orderkey IN (SELECT l_orderkey FROM lineitem GROUP BY l_orderkey HAVING SUM(l_quantity) > 300)
  AND c_custkey = o_custkey AND o_orderkey = l_orderkey
GROUP BY c_name, c_custkey, o_orderkey, o_orderdate, o_totalprice
ORDER BY o_totalprice DESC, o_orderdate
LIMIT 100
```

## Grounded candidate walls / gaps (measure the order — it determines the next ADR)
1. **`o_orderkey IN (SELECT l_orderkey … GROUP BY l_orderkey HAVING SUM(l_quantity) > 300)`** — the likely first
   wall. `LIMIT` is not the wall: SQL `LIMIT` already lowers to `LogicalPlan::Take` or `Sort { limit: … }`, and
   `ExecutionPlan::Take` exists. The IN body is the real new shape: membership-subquery lowering reuses the
   EXISTS-shape validator, and that validator currently rejects `GROUP BY` / `HAVING`. The diagnostic prize comes
   after that shape is admitted: **if the grouped-aggregate membership input then reds on the same
   `unsupported_cross_join`/broadcast-build-side path as q15, that is shared evidence** → q15 + q18 consolidate
   behind one composite-join engine ADR.
2. **Fixture gap — `o_totalprice` absent** from orders. **Deferred (measure-first):** the grouped-IN reject is
   `@plan`; `o_totalprice` resolution is `@bind` (later). Add it only if the measured wall reaches bind and proves
   it is needed (the q13/`o_comment` pattern, ADR 307).
3. Not q11's wall: inner `HAVING SUM(l_quantity) > 300` is a **literal** threshold, not a scalar subquery. Plain
   top-level HAVING is supported, but HAVING inside the membership subquery is still blocked by the restricted
   subquery-shape validator. The 3-table `customer ⋈ orders ⋈ lineitem` (base relations, keyable), the 5-key GROUP
   BY, 2-key ORDER BY, and top-level `LIMIT 100` are precedented.

## Decision

Add q18 dev+strict, **official shape including `LIMIT 100`**, `:1` quantity threshold = `300`, `STRICT_Q18_SQL =
Q18_DEV_SQL`. **Verify-first, measure-first** — classify only the measured wall, never the predicted one; no
speculative fixtures. **Not mode-agnostic** (`o_totalprice` + `SUM(l_quantity)` Decimal/Float64).

### D1 — fixtures: none up front (`o_totalprice` is the contingency)
`q18_tables(strict, sf)` over `customer` + `orders` + `lineitem` (existing fixtures). **Contingency only:** if the
measured wall reaches `@bind` on `o_totalprice` not-found *after* the grouped-IN `@plan` wall moves, add `o_totalprice`
(Decimal/Float64, from `OrderGenerator`) + verify no regression on the shared orders fixture
(q03/q04/q05/q10/q12/q13/q22 + goldens). Expected: a `@plan` wall fires first → deferred.

### D2 — wiring
`Q18_DEV_SQL`/`STRICT_Q18_SQL`; `q18_tables`; `run_dev_q18`/`run_strict_q18`; `status_rows`; `main.rs` routes
`"q18"`; matrix row.

### Verify-first — measure
Run q18 at sf=0.01 both modes; record the rows. **No predicted outcome.** Classify the measured wall only when the
raw error is specific enough to do so safely. If the first grouped-IN reject is the shared
`unsupported EXISTS subquery shape` message, do **not** overclassify it as membership-specific from telemetry alone;
record the raw message and keep the broader bucket. Reuse an existing reason if it matches — q15's
`unsupported_cross_join`/broadcast-build-side reject *is* the shared-wall confirmation. No pre-solve.

## Acceptance
- q18 dev/strict record **honest** measured rows at sf=0.01. q18 counts as keyed-green reach only if both modes
  `pass@execute`. Reach + correctness unchanged accordingly. No fixture change unless the contingency fires.
- `matrix` includes q18; a harness test pins the measured rows. Results doc records: **which wall fired first**
  (grouped-IN shape vs q15-like composite join vs `o_totalprice`), whether it **matches q15's composite reject** (the shared-wall
  finding), and the resulting next-ADR direction.

## Boundaries
- Reachability only; no q18 correctness oracle. No engine work in this cut. Each measured wall (grouped membership
  subquery, composite IN-semijoin, fixture gap) defers to its own ADR.

## Forward arc — branches on the measured wall
- **Grouped-IN shape first** → next ADR = **membership subqueries over grouped bodies**. This does *not* answer the
  q15/q18 shared composite-join question yet; q18 re-measures after the grouped-IN shape lands.
- **IN-composite later, matching q15** → **shared-wall confirmed**; one composite-join engine ADR unblocks q15 + q18
  (high leverage).
- **IN-composite later, but a different reject** → a distinct composite wall (still useful evidence).
- The measured-wall inventory grows (q11 HAVING-scalar, q15 composite-join, q18 ?, q19/q21 unprobed) → then batch
  the highest-leverage engine cut.

## Why toron-home / harness
A `toron-tpch` reachability addition (query + wiring; fixture add only on the contingency); no `crates/toron`
engine change in this cut. Measured walls name separate engine ADRs. No Wendelon / cross-ring surface.
