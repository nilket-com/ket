# ADR 277 — tpch.q05 reachability attempt (6-table; cyclic join graph)

## Status
Proposed.

## Context
The gauge has five reach cells dev+strict green (q01/q03/q06/q10/q14) and two correctness cells (q06, q01).
Per the cadence, ADR 277 returns to reachability with **tpch.q05** (Local Supplier Volume) — the gauge's
biggest multi-table jump (**6 tables**: customer/orders/lineitem/supplier/nation/region) and, the interesting
part, the first **cyclic/interconnected join graph**. q10 already had a branch through `nation`; q05 adds the
new stressor: multiple equality paths through `supplier`/`nation`. A reachability attempt in the ADR 269/272/274
mold: bring q05 in, run dev + strict, record the first wall; implement no wall. (Council-selected topic.)

q05 shape (tpchgen-2.0.2's exact Q5, `:1` → `'ASIA'`, `:2` → `'1994-01-01'`, interval upper bound literalized
to `DATE '1995-01-01'`, **no LIMIT** — the bundled text carries none):
```sql
SELECT n_name, SUM(l_extendedprice * (1 - l_discount)) AS revenue
FROM customer, orders, lineitem, supplier, nation, region
WHERE c_custkey = o_custkey AND l_orderkey = o_orderkey AND l_suppkey = s_suppkey
  AND c_nationkey = s_nationkey AND s_nationkey = n_nationkey AND n_regionkey = r_regionkey
  AND r_name = 'ASIA'
  AND o_orderdate >= DATE '1994-01-01' AND o_orderdate < DATE '1995-01-01'
GROUP BY n_name
ORDER BY revenue DESC
```

## Grounded wall shortlist (verify-first — the impl measures the reachability run, doesn't assert)
- **Most plausible new wall: the interconnected / multi-predicate join graph.** Unlike q10's left-deep chain
  (+ a single-key nation bridge), q05 is *not* a chain: the supplier relation carries **multiple equality
  predicates** — `l_suppkey = s_suppkey` (its natural join key) plus `c_nationkey = s_nationkey` and
  `s_nationkey = n_nationkey`, which give **two paths from customer to supplier** (via nationkey, and via
  orders→lineitem→suppkey). When the comma-join recognizer (`recognize_cross_equi_joins`) lifts the equalities
  into a left-deep keyed tree, those extra equalities land as additional join keys or residual filters between
  already-joined relations. Whether the binder recognizer + executor handle that multi-key/cross-edge shape at
  6 tables is untested beyond q03/q10's simpler joins — the headline thing to measure. The reachability rail is
  single-node (`plan → bind → execute`); distributed fragmentation remains outside this cut unless q05 later
  nominates it through a separate distributed probe.
- **Probably not the wall:** `GROUP BY n_name` (Utf8 — q10/q01), the revenue arithmetic (q01/q03/271), `ORDER
  BY revenue DESC` (q03), the `r_name = 'ASIA'` string filter, literal date bounds (no `INTERVAL`).

Honest expectation: either a join-graph wall (names the next ADR — join-graph generality, an engine cut) or a
6th green reach cell. The impl **measures** the full q05 attempt and classifies what it observes.

## Decision
Bring q05 into the gauge as a measured row in **both** modes; implement no wall.

1. **q05 SQL, tpchgen-exact.** `:1` → `'ASIA'`, `:2` → `'1994-01-01'`, interval upper bound →
   `DATE '1995-01-01'`, `ORDER BY revenue DESC` only — no LIMIT. Same text both modes; only `lineitem`
   physical types differ. Don't rewrite to dodge the wall.
2. **Fixtures.** **Append `l_suppkey` (Int64)** to the dev + strict `lineitem` fixtures (append-only — existing
   queries don't reference it, so their outputs/digests are unchanged). Add **`supplier`** (`s_suppkey`,
   `s_nationkey` Int64) via `SupplierGenerator` and **`region`** (`r_regionkey` Int64, `r_name` Utf8) via
   `RegionGenerator` (no decimals → identical dev/strict, like `nation`/`part`). **Reuse `nation` as-is** — it
   already carries `n_regionkey` (ADR 274), ready for `n_regionkey = r_regionkey`. customer/orders are already
   present.
3. **Wire + measure precisely (ADR 262).** `run_dev_q05` / `run_strict_q05`, CLI `--query q05`, `status_rows`
   → q05 `implemented`. Run both modes; honest row — `pass`, a **specific** recognized blocker, or an honest
   `fail`. If the join graph walls, add a precise classifier rather than a generic bucket; an unrecognized
   error stays `fail`.

## Watch-items (operator) → guards
- **Append-only `l_suppkey`.** Appended to the end of both `lineitem` schemas; q01/q03/q06/q10/q14 outputs +
  digests and the q06/q01 correctness cells are unchanged (verify the existing tests stay green).
- **No engine feature.** Nothing added to force q05 through; a measured join-graph wall is the honest
  deliverable and names the next ADR.
- **Precise classification.** A blocked row carries a specific recognized reason; unrecognized stays `fail`.
- **`status` stays static inventory** (q05 → `implemented`); the measured row lives only in the matrix.
- **Explicit large-stack test.** q05 is 6-table — deeper than q10's 4-table, which already overflowed
  libtest's default test-thread stack; the q05 harness test runs on the explicit `std::thread::Builder`
  stack-size wrapper (current-thread runtime), not a bare `#[tokio::test]`.
- **Default-scale keyed guard if q05 passes.** If q05 reaches execute, add a dev `sf=0.01` check on the same
  large-stack wrapper. A keyless/cartesian six-table plan must not masquerade as a tiny-scale success; if q05
  blocks before execute, the measured blocker is the gate instead.

## Acceptance
- q05 moves `not_run` → a measured row (pass | specific recognized blocker | honest fail) in both modes; the
  reachability matrix + a harness test render it.
- If blocked, the reason is allowlisted with a precise classifier and names the next ADR.
- q01/q03/q06/q10/q14 reachability + the q06/q01 correctness cells are unchanged.

## Forward arc
If q05 walls on the join graph → the next ADR is join-graph generality (the engine cut that lands it). If q05
passes, the gauge has a 6th reach cell, and the remaining frontier is the harder arcs: correlated subqueries
(q04/q17/q20/q22), date-interval arithmetic, and distributed/perf probes. A q05 (or q03) correctness oracle
remains available later.

## Why toron-home
The `toron-tpch` reachability gauge + whatever planner/binder/exec wall q05 surfaces. No cross-ring surface.
