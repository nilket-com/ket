# ADR 269 — tpch.q14 (first measured row)

## Status
Proposed.

## Context
q01 and q06 are `pass@execute` in both modes; q02–q05, q07–q22 are `not_run`. The gauge advances by bringing
the next TPC-H query in and **measuring** its first wall — the wall names the next ADR (the ADR 262 pattern).
The council picked **tpch.q14**, the smallest multi-table query (`lineitem` + `part`) and the one that
nominates the deferred Decimal-arithmetic arc.

`tpch.q14` reachability shape (official-shaped, with the interval upper bound written as a literal date):
```sql
SELECT 100.00 * SUM(CASE WHEN p_type LIKE 'PROMO%'
                        THEN l_extendedprice * (1 - l_discount) ELSE 0 END)
              / SUM(l_extendedprice * (1 - l_discount)) AS promo_revenue
FROM lineitem, part
WHERE l_partkey = p_partkey
  AND l_shipdate >= DATE '1995-09-01' AND l_shipdate < DATE '1995-10-01';
```

A verify-first probe (full q14 on a strict 2-table `Decimal128` fixture) found q14's first wall is **not** the
headline `÷` the council pre-named — it's the **comma-join**: `FROM a, b WHERE a.k = b.k` binds to a **keyless
CROSS JOIN** (`"CROSS JOIN requires a broadcast-eligible build side … a keyless hash-partition would collapse
the cartesian to a single bucket"`), because the equi-predicate is never lifted into a join key. That wall is
**type-independent**, so it gates dev and strict alike — explicit `JOIN … ON` clears it (the hash-join
machinery is all landed). Behind it, in order: CASE Decimal-vs-`0` unification → Decimal literal in `*` →
scalar Decimal `÷`. So `÷` is q14's *fourth* wall.

## Decision

ADR 269 is a **reachability attempt, not an engine feature.** Bring q14 into the gauge and record its measured
row; do **not** implement any wall in this cut.

1. **Wire q14 (official comma-join shape).** Add `Q14_DEV_SQL` / `STRICT_Q14_SQL` with literal date bounds —
   "official-shaped, not official result," matching q01/q06. **Do not** rewrite the comma-join to explicit
   `JOIN … ON`, the CASE, or the `/` to force progress: the failure *is* the evidence this ADR collects. Using
   non-canonical SQL to dodge a real TPC-H gap would game the gauge.
2. **Multi-table harness.** Generalize the single-table `run_query` (registers `TableId(1)`, one batch) to a
   helper that registers N `(TableId, descriptor, batch)` tables before plan/bind; keep a one-table wrapper so
   q01/q06 are unchanged. Add `lineitem`+`part` fixtures: dev keeps money/discount `Float64`, strict keeps
   `Decimal128(15,2)`; `lineitem` gains `l_partkey`, `part` is `(p_partkey Int64, p_type Utf8)` with a PROMO
   and a non-PROMO row. Seed realistic optimizer facts for the harness tables (facts are catalog-side, not a
   `TableSchemaDescriptor` field) so the measured wall is the genuine wall, not an artifact of an
   underspecified build side.
3. **Measure and classify precisely.** Run q14 dev + strict and record the row. Add a **specific** recognized
   blocker for the measured reason — do not bury it under `unsupported_query_surface`, since this row's job is
   to name the next cut. Per the probe the expected reason is the comma-join cross-join (a new
   `unsupported_cross_join`); the impl **re-measures against the real fixtures and classifies whatever it
   observes** (see Watch-items).

## Watch-items (operator) → guards
- **The measured wall must be the real one.** The probe's descriptor-only fixture carried no optimizer facts,
  so `part` was not broadcast-eligible and the cross-join was rejected outright. With realistic catalog facts,
  a tiny `part` *might* be broadcast-eligible — the cross-join could be admitted and q14 then walls later
  (CASE Decimal unification). The impl seeds `part` honest facts and asserts **the reason it actually
  measures**, not the probe's predicted one. The ADR's value is the honest row.
- **No engine feature.** A blocked row is green only if its reason is recognized *and* specific. Nothing is
  added merely to make q14 pass; strict mode stays `Decimal128` (no Float64 shortcut). q01/q06 rows and
  digests unchanged.
- **`status` stays static capability inventory** (q14 → `implemented`); the measured pass/blocked lives only
  in the JSONL-backed matrix.
- The verify-first probe is kept as a grounding regression for the no-facts comma-join shape; the harness
  tests separately assert the actual q14 row measured with seeded optimizer facts.

## Acceptance
- q14 moves `not_run` → a measured, recognized, specific blocked (or pass) row in **both** modes; the matrix
  and harness tests render it.
- The measured reason is allowlisted in `RECOGNIZED_BLOCKERS` with a precise `reason_for_error` classifier
  (not the generic surface bucket).
- q01/q06 unchanged; `status` inventory unchanged in shape.

## Forward arc (named by the measured row)
- **If the measured row is comma-join cross-join:** ADR 270 = comma-join equi-join recognition — lift `Filter(a.k =
  b.k)` over `CrossJoin` into the inner hash-join the explicit form already produces. Foundational: every
  multi-table TPC-H query is comma-joined, so it unblocks the whole join frontier.
- **Then the Decimal mini-arc** (q14's walls 2–4, a tight follow-on sequence): CASE Decimal-vs-integer
  unification → extend ADR 266's Decimal-literal coercion to `*` → scalar `Decimal ÷ Decimal` (the binary
  `Operator::Divide` arm reusing 268's i128 half-away-from-zero divide; `s_out = max(s)+6`, div-by-zero → NULL
  per ADR 084).

## Why toron-home
`toron-tpch` reachability gauge — the harness and its telemetry. No cross-ring surface.
