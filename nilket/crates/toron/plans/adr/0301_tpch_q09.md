# ADR 301 — tpch.q09 reachability

## Status
Proposed.

## Context

The reach frontier reopens after the level-board milestone (13 reach / 13 correctness). q09 is the next reach probe:
it reuses the now-open large comma-join + derived-aggregation + Decimal + EXTRACT/ORDER-BY surfaces, but adds two
stressors the green set hasn't clearly proven: a **`%green%` contains-LIKE** and a **strict profit subtraction of
two independently-derived Decimal products**.

```sql
SELECT nation, o_year, SUM(amount) AS sum_profit
FROM (
  SELECT n_name AS nation, EXTRACT(year FROM o_orderdate) AS o_year,
         l_extendedprice * (1 - l_discount) - ps_supplycost * l_quantity AS amount
  FROM part, supplier, lineitem, partsupp, orders, nation
  WHERE s_suppkey = l_suppkey AND ps_suppkey = l_suppkey AND ps_partkey = l_partkey
    AND p_partkey = l_partkey AND o_orderkey = l_orderkey AND s_nationkey = n_nationkey
    AND p_name LIKE '%green%'
) AS profit
GROUP BY nation, o_year ORDER BY nation, o_year DESC
```

## Decision

Add q09 dev+strict, official Q9 shape (`:1`→`'green'`), no LIMIT, `STRICT_Q9_SQL = Q9_DEV_SQL` (strictness from
table physical types). **Verify-first** — harness-only unless a measured wall appears (then → ADR 302).

### D1 — fixtures (none new); `q09_tables` assembled directly
`q09_tables(strict, sf)` = **exactly** `part`, `supplier`, `lineitem`, `partsupp`, `orders`, `nation` (6 physical
relations), assembled from the existing per-table builders (`generate_partsupp` etc.). **Do not filter
`q08_tables`** — q08 carries `customer`/`region` and lacks `partsupp`; q09's set is different. No new fixture
columns; the required `part`, `partsupp`, and `lineitem` columns already exist.

### D2 — wiring
`Q9_DEV_SQL`/`STRICT_Q9_SQL`; `q09_tables`; `run_dev_q09`/`run_strict_q09`; `status_rows`; `main.rs` routes
`"q09"|"q9"`; matrix row.

### Verify-first — measure the first wall (don't predict)
Run q09 at **sf=0.01**; record the measured row. Candidate walls, in expected order:
1. **`LIKE '%green%'` (contains):** `evaluate_like` delegates to the Arrow LIKE kernel, which handles general
   `%x%` patterns, so this *should* pass — but the TPC-H path hasn't exercised a contains pattern (only q14
   prefix / q02 suffix). If it walls, that's the measured blocker, not a rewrite.
2. **The profit subtraction:** strict `(Decimal*Decimal) − (Decimal*Decimal)`. The two products share scale 4 but
   may have **different derived precision** — a potential **Decimal *arithmetic*-alignment gap, distinct from
   ADR 283/286 *comparison* alignment**. The likeliest genuinely-new wall.
3. **The 6-way derived comma join** (incl. the partsupp composite key `ps_suppkey=l_suppkey AND
   ps_partkey=l_partkey`): ADR 270/294 + q02 (same composite key, reach-green) should cover it, but it **must be
   keyed at sf=0.01** — a cartesian is an honest red, not a pass.

`pass@execute` both modes → reach **14**. Otherwise the measured row names ADR 302. Add a blocker classifier only
for a narrow, recognizable wall; generic failures stay `fail(unrecognized@phase)` with the raw error documented.
No query rewrite.

## Boundaries
- Reachability only; no q09 correctness oracle. No engine work unless a wall is measured. No new fixtures; six
  physical relations, assembled directly.
- **For the *future* q09 correctness:** `amount` (revenue − cost) is a **new arithmetic shape** for the rail (the
  first subtraction-of-products profit); the oracle will mirror it + must measure non-emptiness of the `'%green%'`
  parts.

## Acceptance
- `q09 dev=pass@execute strict=pass@execute` at sf=0.01 (keyed), or an honest measured red naming ADR 302.
- `matrix` includes q09; existing reach + correctness rows unchanged. Documented in
  `crates/toron/plans/impl/0301_tpch_q09_results.md` (measured phase/status/reason; **whether non-empty at
  sf=0.01**, for the future oracle).

## Forward arc
If green: reach → 14; the 2:1 cadence resumes (1 reach done → 2 catchups, q09's subtraction-profit a natural
candidate). q13/q19/q22 remain further reach machetes. If a wall: ADR 302 (likeliest the Decimal
arithmetic-alignment gap or contains-LIKE) — a real engine cut.

## Why toron-home / harness
A `toron-tpch` reachability addition (query + wiring; no new fixtures). No `crates/toron` engine change expected;
a measured wall scopes ADR 302 separately.
