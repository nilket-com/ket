# ADR 284 — Implementation plan: tpch.q02 reachability

Pairs with `plans/adr/0284_tpch_q02.md`. Engine cut (D1) + harness (D2). Function names are current-tree anchors.

## Phase 0 — measure
Add the smallest q02 attempt (or a temporary probe; remove before sealing) and record the raw first wall in the
results doc. Grounded expectation: `"non-aggregate scalar subqueries are not supported"` from
`validate_aggregate_scalar_subquery_shape` (`from.len()==1`).

## D1 — engine: multi-table-inner correlated scalar (`crates/toron/src`)

**Step 1 — split / relax the scalar-subquery gate** (`validate_aggregate_scalar_subquery_shape`).
Separate the scalar-aggregate *shape* checks (SELECT body; no GROUP BY/HAVING/DISTINCT; exactly one
aggregate-bearing projection; aggregate args not outer-correlated; not a non-aggregate scalar) from the
*single-source* check. The deferred-correlated path accepts `from.len() >= 1` with every `from[i].joins.is_empty()`
(explicit JOIN syntax stays deferred); the uncorrelated/qualified paths keep the single-source gate unless their
inner lowering is generalized too. `scalar_subquery_inner_qualifiers` must return qualifiers for **all** FROM
entries so the inner scope spans the comma-join.

**Step 2 — lower the full inner `FROM`** (deferred branch in `pull_up_scalar_subqueries`). Replace
`lower_table_factor(&select.from[0].relation)` with a left-deep comma-join over `select.from`. Prefer extracting a
shared helper from `lower_select`'s FROM lowering rather than copying it, e.g.
`fn lower_from_list(&self, from: &[TableWithJoins], cte: &CteScope) -> Result<LogicalPlan, FrontendError>`,
preserving join-chain behavior (comma lists → left-deep keyless `Cross`). If a shared helper is too large, use a
narrower scalar-inner helper but pin it with a q02-like regression so it can't silently drop `from[1..]` again.
The branch still collects every `WHERE` conjunct into `predicates` and keeps the ADR 282 projection-wrapper
rewrite + the COUNT/DISTINCT rejects. Generalize the qualified-correlated path in lockstep if the gate is relaxed
for it.

**Step 3 — key the inner comma-join** (`bind_deferred_scalar_subquery`). After building
`inner_filtered = Filter(residuals, inner.clone())` and **before** wrapping it in the `Exchange`/`Aggregate`, run
the existing cross-equi recognizer on that residual-filtered plan so the inner-join equalities lift to keyed
inner joins (else a multi-table inner binds as a cartesian — the top-level recognizer already ran, before this
filter existed). Keep the call scratch-trace clean; the final scalar recombine remains the only plan that records
real join replay state. No classifier change: `classify_deferred_scalar_predicate` already routes inner-only
predicates → `InnerResidual` and the correlation pair → `Correlated`.

**Step 4 — binder/executor expectations.** No new IR variant. `DeferredScalarSubquery.inner` already holds an
arbitrary plan and `bind_deferred_scalar_subquery` probe-binds it on scratch trace state. Expected routing:
correlated pair `p_partkey`↔`ps_partkey`; inner residuals `s_suppkey = ps_suppkey`, `s_nationkey = n_nationkey`,
`n_regionkey = r_regionkey`, `r_name = 'EUROPE'`. If Step 3 still leaves a cartesian, record the raw wall and fix
here or name a precise follow-on — do not let q02 pass only at tiny scale.

## D2 — harness (`crates/toron-tpch/src/lib.rs`)
1. Import `PartSuppGenerator` (the `tpchgen::generators` import at `:22`).
2. `part` += `p_size` Int32, `p_mfgr` Utf8 (`part_schema`, `generate_part` `:437`).
3. Make supplier mode-sensitive: `supplier_schema(strict)`, `generate_supplier(strict, sf)`; keep
   `supplier_descriptor(schema.as_ref())` on the existing descriptor pattern. Append `s_acctbal` (Float64 dev /
   Decimal128(15,2) strict), `s_name`, `s_address`, `s_phone`, `s_comment`. Thread `strict` through
   `q05_tables` (q05 unchanged — it doesn't reference the appended columns; verify its digest is stable).
4. `partsupp`: `partsupp_schema(strict)` (`ps_partkey` Int64, `ps_suppkey` Int64, `ps_availqty` Int32,
   `ps_supplycost` Float64/Decimal128(15,2)); `partsupp_descriptor` (`TableObjectId::new([20;16])`, AppendOnly +
   `MultiRow`); `generate_partsupp(strict, sf)`. `facts_for_batch` on every q02 table.
5. SQL + runners: `Q2_DEV_SQL` (official text below), `STRICT_Q2_SQL = Q2_DEV_SQL`, `q02_tables(strict, sf)`
   (part/supplier/partsupp/nation/region), `run_dev_q02`/`run_strict_q02`, `status_rows` entry, matrix row.
6. CLI (`main.rs`): import + route `"q02" | "q2"`.

```sql
SELECT s_acctbal, s_name, n_name, p_partkey, p_mfgr, s_address, s_phone, s_comment
FROM part, supplier, partsupp, nation, region
WHERE p_partkey = ps_partkey AND s_suppkey = ps_suppkey AND p_size = 15 AND p_type LIKE '%BRASS'
  AND s_nationkey = n_nationkey AND n_regionkey = r_regionkey AND r_name = 'EUROPE'
  AND ps_supplycost = (SELECT MIN(ps_supplycost) FROM partsupp, supplier, nation, region
    WHERE p_partkey = ps_partkey AND s_suppkey = ps_suppkey AND s_nationkey = n_nationkey
      AND n_regionkey = r_regionkey AND r_name = 'EUROPE')
ORDER BY s_acctbal DESC, n_name, s_name, p_partkey
```

## Tests
- **Engine-level** (`crates/toron/tests/correlated_scalar_test.rs` — multi-table inner is the ADR 282 feature
  generalized): a correlated scalar with a **2-table inner** binds + executes correct rows over matching data
  (discriminating: pre-cut rejects at the single-source gate — revert→fail→restore); a **negative control** that
  a non-aggregate scalar subquery still rejects; a tractability/no-inner-cartesian assertion (oversized-build
  lever or row-count) locking D1 #3.
- **Gauge** (`toron-tpch/tests/harness.rs`): q02 dev+strict — `pass@execute` with a digest, or a precise
  classified wall; inventory/status assertions. Use the q10/q05 explicit-64MB-stack pattern (q02 is the deepest
  gauge query: 5-table outer + 4-table inner + recombine). If it reaches execute, assert `sf=0.01` dev+strict
  pass (keyed/tractable, not a hollow tiny-scale green).

## Risk / blast radius
- The gate split + inner lowering touch the **shared** scalar pull-up — uncorrelated/qualified paths must stay
  correct under the split gate (Step 2 generalizes the qualified path so it can't drop inner tables). Full
  `--no-fail-fast` is the net.
- D1 #3 re-runs the recognizer on the inner — the inner-cartesian is the failure mode it prevents; verify via the
  tractability test, not just bind-green.
- Deepest gauge query yet — use the explicit-64MB-stack test pattern from the start.
