# Implementation Plan — ADR 272: tpch.q03 (first 3-table reachability attempt)

## Summary
A harness reachability attempt, not an engine cut. Add `customer` + `orders` fixtures, append `l_orderkey` to
`lineitem`, wire the tpchgen-exact q03 SQL (no LIMIT) through the ADR 269 multi-table harness, run it dev +
strict, and record the measured outcome as `pass`, a **specific** recognized blocker, or an honest `fail` if
the reason is unrecognized. No wall is implemented. Scoped to `toron-tpch`.

## Phase 0 — verify the board
`scripts/cargo-cgroup run -p toron-tpch -- matrix` → q01/q06/q14 `pass@execute`, q03 `not_run`, and all
non-attempted queries still `not_run`.

## Phase 1 — fixtures (`crates/toron-tpch/src/lib.rs`)
- **`l_orderkey`**: append `Field::new("l_orderkey", DataType::Int64, false)` to the dev **and** strict
  `lineitem` schemas + generators (`generate_dev_lineitem` / `generate_strict_lineitem`, pushing
  `item.l_orderkey`). Append-only, like ADR 269's `l_partkey`, so q01/q06/q14 column positions and the q06
  digest don't move.
- **`customer`**: `generate_customer` from `tpchgen::generators::CustomerGenerator` → `(c_custkey Int64,
  c_mktsegment Utf8)` (only the q03-needed columns); `customer_schema` / `customer_descriptor`. No decimals →
  identical dev/strict (like `part`).
- **`orders`**: `generate_orders` from `OrderGenerator` → `(o_orderkey Int64, o_custkey Int64, o_orderdate
  Date32, o_shippriority Int32)`; `orders_schema` / `orders_descriptor`. (Confirm the generator field names /
  the `o_orderdate` → `Date32` conversion mirror q14's `l_shipdate` path.)
- `facts_for_batch` for each of the three batches (honest row/byte bounds), as q14 does.

## Phase 2 — q03 SQL (`lib.rs`)
- `Q3_DEV_SQL` / `STRICT_Q3_SQL` = tpchgen's Q3 text with `:1` → `'BUILDING'`, `:2` → `DATE '1995-03-15'`
  (both date comparisons use the same date), **no LIMIT**. Same text both modes. Do not rewrite the comma
  join, GROUP BY, or ORDER BY.

## Phase 3 — wiring (`lib.rs` + `main.rs`)
- `run_dev_q03` / `run_strict_q03`: build the three `HarnessTable`s (`lineitem` TableId(1), `customer`
  TableId(2), `orders` TableId(3) — q03 is `run_query_with_tables`'s first 3-table user) and call it.
- CLI dispatch: `run --query q03 --mode dev|strict` (mirror the q14 arm; q03 resolves `--sf` like any query —
  no scale cap, ADR 270 removed q14's).
- `status_rows`: q03 → `implemented`.

## Phase 4 — measure + classify (`telemetry.rs` if a new reason)
- Run `run --query q03 --mode strict --allow-blocked` and `--mode dev`; read the actual reason from the **full**
  q03 attempt. Per the grounded shortlist the likely wall is GROUP-BY-over-a-join — but record whatever it is.
- If blocked on a new reason, add a **specific** recognized blocker (ADR 262 precise-match, classified before
  any generic bucket). If the reason is already recognized, reuse it. If unrecognized, leave it `fail` (honest)
  — do not force a green. If it `pass@execute`, no telemetry change.

## Phase 5 — tests (`crates/toron-tpch/tests/`)
- `harness.rs`: a q03 test asserting the measured phase/status/reason in both modes (the specific recognized
  reason if blocked, or `pass@execute` + digest if it passes) and q03 `implemented` in `status`. Mirror the q14
  test shape.
- Keep a verify-first probe (the full q03 bind on the 3-table fixtures) as a grounding regression.
- q01/q06/q14 harness tests + the architecture guard + `matrix_from_log` stay green; appending `l_orderkey`
  must not move q01/q06/q14.

## Risk notes
- **Don't move q01/q06/q14.** Append `l_orderkey`; don't reorder existing `lineitem` columns or shift the q06
  digest.
- **Classify what you measure.** Record the real first wall (full q03 attempt); a recognized+specific blocked
  row or an honest `fail` — never a forced green.
- **No LIMIT.** tpchgen-exact shape; top-N is a separate surface.
- **No engine feature.** strict stays `Decimal128`; nothing added to force q03 to pass.
- **Confirm the generators.** `CustomerGenerator` / `OrderGenerator` exist in tpchgen-2.0.2 (the queries module
  uses these tables); verify the exact field accessors + the `o_orderdate` Date32 conversion before wiring.
