# ADR 315 — Implementation plan: tpch.q18 reachability

Pairs with `plans/adr/315_tpch_q18.md`. Harness-only (`toron-tpch`); no `crates/toron` engine change in this cut.
Verify-first, measure-first. The measured wall order determines the next ADR (grouped-membership shape vs
composite-join vs fixture gap).

## Phase 0 — verify-first probe (measure; do not predict)
Wire the minimum and **measure both modes**:
```
target/debug/toron-tpch run --query q18 --mode dev    --sf 0.01 --allow-blocked
target/debug/toron-tpch run --query q18 --mode strict --sf 0.01 --allow-blocked
```
**Record both raw rows verbatim** — the first wall determines the classifier *and* the forward arc:
- `@plan` on the grouped membership subquery shape → next is membership-subquery bodies over grouped aggregate
  inputs (shared-wall question unanswered).
- later `@plan`/`@bind` on the IN-over-grouped-aggregate composite input → compare the reject to q15's
  `unsupported_cross_join`/broadcast-build-side message; a match = shared-wall confirmation.
- `@bind` on `o_totalprice` not-found → the D1 contingency (add the column, re-measure).
Don't leave probe code behind.

## D1 — fixtures: none up front (contingency only)
`fn q18_tables(strict, sf)` over `customer` (`generate_customer`) + `orders` (`generate_orders`) + `lineitem`
(`generate_{dev,strict}_lineitem`); `facts_for_batch` each. **Contingency:** only if Phase-0 shows `o_totalprice`
not-found `@bind` *after* the grouped-IN `@plan` wall moves — append `o_totalprice` (Decimal128(15,2)/Float64) to `orders_schema`
+ populate from `OrderGenerator.o_totalprice`; then full `-p toron-tpch` + both matrices + orders goldens to prove
q03/q04/q05/q10/q12/q13/q22 unmoved (postcard-preimage caution). Expected: skip.

## D2 — wiring — `lib.rs` + `main.rs`
- `Q18_DEV_SQL` (official q18: `customer, orders, lineitem` on `c_custkey = o_custkey AND o_orderkey = l_orderkey`;
  `o_orderkey IN (SELECT l_orderkey FROM lineitem GROUP BY l_orderkey HAVING SUM(l_quantity) > 300)`; `GROUP BY
  c_name, c_custkey, o_orderkey, o_orderdate, o_totalprice`; `SUM(l_quantity)`; `ORDER BY o_totalprice DESC,
  o_orderdate`; `LIMIT 100`); `STRICT_Q18_SQL = Q18_DEV_SQL`.
- `q18_tables`; `run_dev_q18`/`run_strict_q18` via `run_query_with_tables("q18", …, q18_tables(strict, sf))`.
- `status_rows()` — add `"q18"`; matrix row. `main.rs` — route `"q18"` (dev/strict).

## D3 — classifier (match the measured wall)
- Grouped-membership reject → add a specific reason only if the raw message is specific enough. If the frontend
  returns the shared `unsupported EXISTS subquery shape` text, keep the broader classification and record the raw
  message in the results doc rather than overclassifying every EXISTS-shape rejection as q18's wall.
- IN-over-composite reject → if it's q15's `unsupported_cross_join` (broadcast-build-side), it already classifies;
  record the **shared-wall** match explicitly. A different composite reject → a precise new reason if the raw message
  supports one.
- Generic/unrecognized → keep `fail(unrecognized@phase)` + document the raw error (no broad classifier).

## Tests — `crates/toron-tpch/tests/harness.rs`
- `q18_blocks_on_<measured-wall>` (the measured shape): dev + strict at sf=0.01 assert the measured
  `Status`/`Phase`/`reason`. 64MB-stack thread if deep.
- `reason_for_error_classifies_<wall>_precisely` (telemetry unit) if a new reason is added — pin the no-overclassify
  boundary.
- **No-regression** — existing reach (q01-11/12/13/14/16/17/20/22) + the 17 correctness cells stay green; no
  fixture change (unless the contingency fired).

## Phase 3 — record the diagnostic finding
Results doc records: which wall fired first (grouped-membership shape / IN-composite / `o_totalprice`); the raw
reject; **whether the IN-composite reject matches q15's composite/broadcast-build-side path** (shared-wall evidence
yes/no); the resulting next-ADR direction (grouped-membership support vs shared composite-join cut). If a mode
reaches execute, its keyed-plan check + non-emptiness for the future oracle.

## Risk / blast radius
- Harness-only (expected). No fixture change in the expected path → low blast radius; the full `-p toron-tpch`
  suite + matrices are the net.
- **Contingency fixture add** (`o_totalprice`, if forced) touches the shared orders fixture — full suite + goldens
  mandatory then.
- **Don't pre-solve** grouped-membership bodies or the composite IN-semijoin — measure + defer each to its own
  engine ADR.
- **The forward arc branches on the measured wall** — grouped-membership-shape first answers a different question
  than IN-composite first; record which, honestly.
