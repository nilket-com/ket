# Implementation Plan — ADR 281: tpch.q17 reachability attempt

## Summary
A harness reachability attempt (not an engine cut): append two columns to the existing `part` fixture (confirm
the `lineitem` money columns), wire the tpchgen-exact q17 SQL (correlated scalar subquery), run dev + strict,
and record the measured first wall. Scope: `crates/toron-tpch`. q17 carries one genuinely-unresolved scalar
class beyond ADR 260's bare correlated aggregate scalar: an unqualified outer reference inside a scalar subquery
whose projection wraps the aggregate (`0.2 * AVG(...)`). The measured first wall names the next ADR — measured,
not asserted.

## Phase 0 — verify the board, then probe empirically
`matrix` → q01/q03/q04/q05/q06/q10/q14 `pass@execute`, q17 `not_run`; `correctness-matrix` → q06/q01/q03
`pass@compare`. Then wire q17 (Phases 1–3) and **run it before naming any classifier** — the row, its phase,
and the reject message come from the gauge, not from this plan. Expected fork:
- The official unqualified `l_partkey = p_partkey` may bind as an unresolved inner-column reference before the
  scalar decorrelator can act.
- If correlation is recognized, the next wall is likely ADR 260's bare-aggregate boundary:
  `0.2 * AVG(l_quantity)` is a wrapped correlated aggregate scalar projection.
If q17 instead passes, record that (first correlated-scalar cell) and pivot.

## Phase 1 — fixtures (append-only, `lib.rs`)
- **part**: append `Field::new("p_brand", DataType::Utf8, false)` and `Field::new("p_container", DataType::Utf8,
  false)` to `part_schema`; push `item.p_brand.to_string()` / `item.p_container.to_string()` in `generate_part`
  (after `p_type`). q17's filters are `p_brand = 'Brand#23'` and `p_container = 'MED BOX'`.
- **lineitem**: confirm the dev + strict lineitem fixtures expose `l_quantity` + `l_extendedprice` (the q01/q06
  money columns) and `l_partkey` (q14); append only what q17 needs and a fixture lacks.
- Append-only: q01/q03/q04/q05/q06/q10/q14 reference none of the new columns, so their outputs/digests + the
  q06/q01/q03 correctness cells are unchanged (confirm in Phase 4).

## Phase 2 — q17 SQL (`lib.rs`)
`Q17_DEV_SQL` / `STRICT_Q17_SQL` = tpchgen Q17 with `:1` → `'Brand#23'`, `:2` → `'MED BOX'`, no LIMIT. Keep
the official unqualified `l_partkey = p_partkey` correlation predicate:
```sql
SELECT SUM(l_extendedprice) / 7.0 AS avg_yearly
FROM lineitem, part
WHERE p_partkey = l_partkey AND p_brand = 'Brand#23' AND p_container = 'MED BOX'
  AND l_quantity < (SELECT 0.2 * AVG(l_quantity) FROM lineitem WHERE l_partkey = p_partkey)
```
Start with the same exact text in both modes. If strict walls only on harness literal typing (`7.0` / `0.2`)
before the intended scalar-correlation wall, introduce the narrow strict literal variant the measured error
requires and record the deviation in the results doc. Do not qualify `p_partkey` or rewrite the subquery to
pre-decorrelate it; the official shape is the measurement.

## Phase 3 — wiring (`lib.rs` + `main.rs`)
- `q17_tables(strict, scale_factor)` = `lineitem` (`TableId(1)`, mode-sensitive) + `part` (`TableId`, reuse
  q14's part id) — q17's FROM is `lineitem, part` with the scalar subquery over `lineitem`.
- `run_dev_q17` / `run_strict_q17` via `run_query_with_tables`. CLI: `run --query q17 --mode dev|strict` (mirror
  the q14 arm). `status_rows` → q17 `implemented`.

## Phase 4 — measure (+ classifier only if a blocker appears)
- Run `run --query q17 --mode dev|strict --allow-blocked` + `matrix`; record the measured row from the **full**
  q17 attempt. Read the actual error: if it walls on unqualified scalar correlation or wrapped correlated
  aggregate scalar projection, add a precise recognized blocker matching the **actual** message (not a guessed
  string, not a generic bucket); if it passes, q17 is the 8th reach cell. Don't force a row.
- Re-run the existing reachability suite + q06/q01/q03 correctness checks → confirm the seven reach cells stay
  green and the correctness cells stay `pass@compare` after the column appends.

## Phase 5 — tests (`tests/harness.rs`)
- A q17 test asserting the measured row in both modes (pass `@execute` + digest, or `blocked` at its phase with
  the precise reason) and q17 `implemented` in `status`. Start with a bare `#[tokio::test]`; fall back to the
  explicit `std::thread::Builder::stack_size(64 MB)` + current-thread wrapper if the future overflows libtest's
  default stack (the q10/q05 pattern).
- If a correlated-scalar classifier lands, a `reason_for_error` unit assertion pinning the exact measured
  message → reason.
- q01/q03/q04/q05/q06/q10/q14 reachability + the q06/q01/q03 correctness tests stay green (the appends are
  transparent).

## Risk notes
- **Empirical Phase 0, no overfit.** The first wall may be unresolved unqualified outer ref, wrapped aggregate
  projection, or something else; the recognized-blocker string + the next-ADR name are set from the gauge's
  actual output.
- **Pivot if it passes.** A `pass` is a real outcome (first correlated-scalar cell); don't force a wall.
- **Don't move the seven green cells.** The new `part` columns are appended; existing queries + correctness
  cells stay byte-stable (verify, don't assume).
- **Keep the real shape — measure, don't dodge.** Canonical correlated scalar subquery; no rewriting to a
  decorrelated join or literalizing to isolate.
- **No engine feature.** strict stays `Decimal128`; the measured wall (or pass) is the deliverable.
