# ADR 313 — Implementation plan: tpch.q15 reachability

Pairs with `plans/adr/0313_tpch_q15.md`. Harness-only (`toron-tpch`); no `crates/toron` engine change expected, no
fixture change. Verify-first.

## Phase 0 — verify-first probe (likely green)
Wire the minimum and **measure**:
```
target/debug/toron-tpch run --query q15 --mode dev    --sf 0.01 --allow-blocked
target/debug/toron-tpch run --query q15 --mode strict --sf 0.01 --allow-blocked
```
Expected `pass@execute` both modes. **Record the raw error verbatim if it walls** (determines the classifier) —
likeliest at the CTE double-reference or the MAX-scalar-over-CTE. Confirm **keyed by plan shape**, not just
runtime: q15's supplier × revenue cartesian can be small enough at sf=0.01 to finish, so bind the q15 plan in a
focused probe/test and assert the `s_suppkey = supplier_no` equality is represented as an `Inner` join key, not a
keyless `Cross` with a residual filter. Don't leave probe code behind.

## D1 — fixtures: none new
`fn q15_tables(strict, sf)` over `supplier` (`generate_supplier`) + `lineitem` (`generate_{dev,strict}_lineitem`);
`facts_for_batch` each. No new columns (`s_name`/`s_address`/`s_phone`/`s_suppkey`, `l_suppkey`/`l_shipdate`/
`l_extendedprice`/`l_discount` all exist).

## D2 — wiring — `lib.rs` + `main.rs`
- `Q15_DEV_SQL` (official q15 WITH-CTE form: `WITH revenue AS (SELECT l_suppkey AS supplier_no,
  SUM(l_extendedprice*(1-l_discount)) AS total_revenue FROM lineitem WHERE l_shipdate >= DATE '1996-01-01' AND
  l_shipdate < DATE '1996-01-01' + INTERVAL '3' MONTH GROUP BY l_suppkey)` then `SELECT s_suppkey, s_name,
  s_address, s_phone, total_revenue FROM supplier, revenue WHERE s_suppkey = supplier_no AND total_revenue =
  (SELECT MAX(total_revenue) FROM revenue) ORDER BY s_suppkey`); `STRICT_Q15_SQL = Q15_DEV_SQL`.
- `q15_tables`; `run_dev_q15`/`run_strict_q15` via `run_query_with_tables("q15", …, q15_tables(strict, sf))`.
- `status_rows()` — add `"q15"`; matrix row. `main.rs` — route `"q15"` (dev/strict).

## D3 — classifier (only if it walls)
If Phase-0 shows a wall, add a **specific** telemetry reason matching the raw reject (narrow, before the generic
buckets, no overclassification) + a unit test. Expected: not needed (likely green).

## Tests — `crates/toron-tpch/tests/harness.rs`
- `q15_executes_in_both_modes_at_default_scale` (or the measured-wall assertion): dev+strict at sf=0.01,
  `Status::Pass` / `Phase::Execute` + digest (dev/strict differ — `total_revenue` Decimal vs Float64). 64MB-stack
  thread if deep.
- **Keyed supplier/revenue plan shape** — add a discriminating assertion (module-local unit test or narrow test
  helper) that binding q15 produces an inner keyed join for `s_suppkey = supplier_no`; do not rely on timing as the
  proof, because this particular cartesian is not guaranteed to be loud at sf=0.01.
- **No-regression** — existing reach (q01-10/12/13/14/16/17/20/22) + the 17 correctness cells stay green; no
  fixture change.

## Phase 3 — confirm + record for the future oracle
- `pass@execute` → flip the q15 harness row to green; reach → 18. Confirm the supplier/revenue equality is keyed
  by plan shape.
- Record (results doc): dev + strict digests; whether the output is **non-empty**; **whether there are ties**
  (multiple suppliers at the max revenue) at sf=0.01 — the `= MAX` tie-set is the load-bearing case for the future
  q15 correctness oracle.
- A wall → record the precise reason (next ADR); no broad classifier.

## Risk / blast radius
- Harness-only (expected). No fixture change → low blast radius; the inherited full seal gate plus the q15 live
  runs are the net.
- **Verify keyed by plan shape** — the CTE must not materialize a cross; default-scale runtime is useful evidence
  but not sufficient for q15 because the cartesian may be small.
- **If it walls** — precise classifier (CTE double-reference / MAX-scalar-over-CTE), defer the engine cut; don't
  pre-solve.
- q15 is **not** mode-agnostic (`total_revenue` Decimal/Float64) — dev and strict digests differ.
