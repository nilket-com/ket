# ADR 307 — Implementation plan: tpch.q13 reachability

Pairs with `plans/adr/307_tpch_q13.md`. Harness-only (`toron-tpch`); no `crates/toron` engine change (the
non-equi-`ON` is ADR 308), and **no fixture change expected**. Anchors are current-tree. Verify-first.

## Phase 0 — verify-first probe (measure which wall fires first)
Wire the minimum and **measure**:
```
target/debug/toron-tpch run --query q13 --mode dev   --sf 0.01 --allow-blocked
target/debug/toron-tpch run --query q13 --mode strict --sf 0.01 --allow-blocked
```
Expected: `blocked(...@plan)` on the non-equi `ON` conjunct: `"join ON only supports equality predicates"`.
That `lower_join_on` reject precedes column-resolution, so the absent `o_comment` does **not** surface first.
**Record the raw error verbatim** — it determines the classifier marker.
- **If** the measured wall is instead `o_comment` column-not-found (binding), THEN add `o_comment` (D1
  contingency) and re-measure. Expected: not needed.
- Don't leave probe code behind.

## D1 — fixtures: none (contingency only)
`q13_tables(strict, sf)` over `customer` (reuse `generate_customer`) + `orders` (reuse `generate_orders`) — the
**existing** fixtures, no `o_comment`. **Contingency** (only if Phase-0 shows column-not-found first): append
`o_comment` (Utf8, non-null) to `orders_schema` + populate from `OrderGenerator.o_comment` in `generate_orders`;
then run the FULL `-p toron-tpch` suite + both matrices + any orders-schema/golden assertion to prove q03/q04/q12/
q18/q22 unmoved (postcard-preimage caution). Expected: skip this.

## D2 — wiring — `lib.rs` + `main.rs`
- `Q13_DEV_SQL` (official q13: `LEFT OUTER JOIN … ON c_custkey = o_custkey AND o_comment NOT LIKE
  '%special%requests%'`; inner `GROUP BY c_custkey` with `COUNT(o_orderkey)`; outer `GROUP BY c_count`,
  `COUNT(*) AS custdist`; `ORDER BY custdist DESC, c_count DESC`); `STRICT_Q13_SQL = Q13_DEV_SQL`.
- `q13_tables`; `run_dev_q13`/`run_strict_q13` via `run_query_with_tables("q13", …, q13_tables(strict, sf))`.
- `status_rows()` — add `"q13"`; matrix row. `main.rs` — route `"q13"` (dev/strict).

## D3 — precise classifier (`telemetry.rs`)
- Add a specific `unsupported_non_equi_join_on` reason in `reason_for_error`, matching the measured
  `lowered.contains("join on only supports equality predicates")` reject — narrow, before the generic
  `unsupported`/`unrecognized` buckets, no overclassification. Do **not** use a broad `"equality predicates"`
  substring that also catches the non-`ON`-constraint guard (`"JOIN requires ON equality predicates"`). Register in
  the recognized-reason list + `status_for_reason`.
- If Phase-0's raw reject doesn't match a narrow marker, record it raw + keep `fail(unrecognized@plan)` (don't
  force a broad classifier) — a sub-finding for ADR 308.

## Tests — `crates/toron-tpch/tests/harness.rs`
- `q13_advances_to_non_equi_join_on_wall` (or the measured shape): dev+strict at sf=0.01 assert `Status::Blocked` /
  `Phase::Plan` / `reason == "unsupported_non_equi_join_on"` (the precise measured wall). 64MB-stack thread if deep.
- `reason_for_error_classifies_non_equi_join_on_precisely` (telemetry unit): the reject message → the reason; an
  unrelated message does **not** match.
- **No-regression** — existing reach (q01-10/12/14/17/20/22) + the 15 correctness cells stay green; **no fixture
  change** (unless the contingency fired).
