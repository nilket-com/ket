# Implementation Plan — ADR 278: tpch.q04 reachability attempt

## Summary
A harness reachability attempt (not an engine cut): append three columns to the existing orders/lineitem
fixtures, wire the tpchgen-exact q04 SQL (official `+ INTERVAL '3' MONTH` + correlated EXISTS), run dev +
strict, and record the measured first wall. Scope: `crates/toron-tpch`. q04 carries two new classes
(official calendar-interval expression, correlated subquery); the measured first wall decides the next ADR —
measured, not asserted.

## Phase 0 — verify the board
`matrix` → q01/q03/q05/q06/q10/q14 `pass@execute`, q04 `not_run`; `correctness-matrix` → q06 + q01
`pass@compare`.

## Phase 1 — fixtures (append-only, `lib.rs`)
- **orders**: append `Field::new("o_orderpriority", DataType::Utf8, false)` to `orders_schema`; push
  `item.o_orderpriority.to_string()` in `generate_orders`.
- **lineitem (dev + strict)**: append `l_commitdate` + `l_receiptdate` (`Date32`) to `dev_lineitem_schema` /
  `strict_lineitem_schema`; push `item.l_commitdate.to_unix_epoch()` / `item.l_receiptdate.to_unix_epoch()` in
  both generators (after `l_suppkey`).
- Append-only: q01/q03/q05/q06/q10/q14 reference none of these, so their outputs/digests + the q06/q01
  correctness cells are unchanged (confirm in Phase 4).

## Phase 2 — q04 SQL (`lib.rs`)
`Q4_DEV_SQL` / `STRICT_Q4_SQL` = tpchgen Q4 with `:1` → `'1993-07-01'`, the interval **kept official**
(`o_orderdate < DATE '1993-07-01' + INTERVAL '3' MONTH`), `ORDER BY o_orderpriority` (no LIMIT). Same text both
modes.

## Phase 3 — wiring (`lib.rs` + `main.rs`)
- `q04_tables(strict, scale_factor)` = `lineitem` (`TableId(1)`, mode-sensitive dev/strict) + `orders`
  (`TableId(3)`) — q04's FROM is `orders` with the EXISTS subquery over `lineitem`; no customer/nation/etc.
- `run_dev_q04` / `run_strict_q04` via `run_query_with_tables`. CLI: `run --query q04 --mode dev|strict`
  (mirror the q10/q05 arms). `status_rows` → q04 `implemented`.

## Phase 4 — measure (+ classifier if a blocker appears)
- Run `run --query q04 --mode dev|strict --allow-blocked` + `matrix`; record the measured row from the **full**
  q04 attempt. Read the actual error: if it walls on `Date32 + CalendarMonthInterval` (which may fold at bind
  because both operands are literals) or on the unqualified correlated ref (EXISTS), add a precise recognized
  blocker matching the actual message (don't let it fall to a generic bucket); if it passes, q04 is the 7th
  reach cell. Don't force a row, don't literalize to isolate.
- Re-run the existing reachability suite + q06/q01 correctness checks → confirm the six reach cells stay green
  and q06/q01 stay `pass@compare` after the column appends.

## Phase 5 — tests (`tests/harness.rs`)
- A q04 test asserting the measured row in both modes (pass `@execute` + digest, or `blocked` at its phase
  with the precise reason) and q04 `implemented` in `status`. Start with a bare `#[tokio::test]`; if the
  decorrelated semi-join future overflows libtest's default stack, move to the explicit
  `std::thread::Builder::stack_size(64 MB)` + current-thread runtime wrapper (the q10/q05 pattern).
- If a date-interval or correlated-EXISTS classifier lands, a `reason_for_error` unit assertion pinning the
  exact message → reason.
- q01/q03/q05/q06/q10/q14 reachability + the q06/q01 correctness tests stay green (the appends are transparent).

Harness-only. (Whichever class q04 walls on, the follow-on engine ADR — calendar-interval expression or

## Risk notes
- **Don't move the six green cells.** The three columns are appended; existing queries + correctness cells stay
  byte-stable (verify, don't assume).
- **Keep the real shape — measure, don't dodge.** Official interval + canonical EXISTS; no literalizing (the
  feature is no longer known-absent). The measured first wall is the honest deliverable.
- **Classify precisely.** A date-interval or unqualified-correlated wall gets a specific recognized reason, not
  a generic bucket; an unrecognized error stays `fail`.
- **No engine feature.** strict stays `Decimal128`; the measured wall (or pass) is the deliverable.
