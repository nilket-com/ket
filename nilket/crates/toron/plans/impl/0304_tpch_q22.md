# ADR 304 — Implementation plan: tpch.q22 reachability

Pairs with `plans/adr/0304_tpch_q22.md`. Harness-only (`toron-tpch`); no `crates/toron` engine change (SUBSTRING is
ADR 305). Anchors are current-tree. Verify-first — measure the first wall, classify it precisely.

## Phase 0 — verify-first probe
Wire the minimum and **measure the real first wall**:
```
target/debug/toron-tpch run --query q22 --mode dev   --sf 0.01 --allow-blocked
target/debug/toron-tpch run --query q22 --mode strict --sf 0.01 --allow-blocked
```
Expected: `blocked(...@plan)` on `SUBSTRING`. A local probe of `SELECT SUBSTRING(c_phone FROM 1 FOR 2) FROM
customer` currently returns `unsupported expression: Substring { ... }` from frontend lowering. **Record the raw
q22 error verbatim** — it determines the classifier marker. Don't leave probe code behind.

## D1 — fixtures: none new
`fn q22_tables(strict: bool, scale_factor: f64) -> Vec<HarnessTable>` over `customer` (reuse `generate_customer`)
+ `orders` (reuse `generate_orders`); `facts_for_batch` on each. No new columns (`c_phone`, `c_acctbal`,
`c_custkey`, `o_custkey` all exist).

## D2 — wiring — `lib.rs` + `main.rs`
- `Q22_DEV_SQL` (official-ish q22; `SUBSTRING(c_phone FROM 1 FOR 2)`; the 7 country codes inlined; the AVG-threshold
  subquery; the correlated `NOT EXISTS`; `GROUP BY cntrycode ORDER BY cntrycode`; no LIMIT); `STRICT_Q22_SQL =
  Q22_DEV_SQL`.
- `q22_tables`; `run_dev_q22`/`run_strict_q22` via `run_query_with_tables("q22", …, q22_tables(strict, sf))`.
- `status_rows()` — add `"q22"`; matrix row. `main.rs` — route `"q22"` (dev/strict).

## D3 — precise classifier (`crates/toron-tpch/src/telemetry.rs`)
- Add a specific `unsupported_substring` reason in `reason_for_error`, matching the SUBSTRING reject (e.g.
  `lowered.contains("substring")` — placed before the generic `unsupported`/`unrecognized` buckets, narrow enough
  not to overclassify). Register it in the recognized-reason list + `status_for_reason`.
- If Phase-0 shows the raw reject does **not** name SUBSTRING (a generic "unsupported expression"), do **not**
  force a classifier — record the raw error, keep `fail(unrecognized@plan)`, and note it (frontend lowering should
  name the expression; that's a sub-finding for ADR 305).

## Tests — `crates/toron-tpch/tests/harness.rs`
- `q22_advances_to_substring_wall` (or the measured shape): dev+strict at sf=0.01 assert `Status::Blocked` /
  `Phase::Plan` / `reason == "unsupported_substring"` (the precise measured wall). 64MB-stack thread if deep.
- `reason_for_error_classifies_substring_precisely` (telemetry unit): the SUBSTRING raw message →
  `unsupported_substring`; an unrelated message does **not** match (no overclassification).
- **No-regression** — existing reach (q01-10/12/14/17/20) + the 14 correctness cells stay green; no fixture change.

## Risk / blast radius
- Harness-only (expected). No fixture change → low blast radius; the full `-p toron-tpch` suite + the two matrices
  are the net.
- **Classifier must be specific** to SUBSTRING — no broad allowlisting (place it before the generic buckets;
  unit-test the no-overclassify boundary).
- **Don't smuggle** the SUBSTRING engine cut, the `NOT EXISTS`, or the `AVG`-threshold into this ADR — measure and
  defer (ADR 305+).
