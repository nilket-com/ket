## D1 — engine: compose subqueries inside a membership body (`crates/toron/src/sql_planner.rs`)

Generalize `lower_membership_subquery` (`:5431`) — keep `validate_exists_*`, the projection-key extraction, and
the returned `(inner_plan, inner_key, correlation_pairs)` shape so the caller's semi/anti-join is unchanged. Only
the body-WHERE handling changes for the uncorrelated membership-body case:

1. **Lower the body FROM** as today: `validate_exists_select_shape` still requires the single body source q20
   uses (`FROM partsupp`). Do not broaden membership-body FROM lists in this cut.
2. **Detect correlated membership bodies** by scanning `split_top_level_and(selection)` for a qualified reference
   to `outer_qualifiers` via
   `sql_expr_references_outer_qualifier(conjunct, outer_qualifiers, &inner_qualifiers)`.
   - If any conjunct references the membership outer query, keep the current restricted path for the whole
     selection: `classify_exists_conjunct` builds correlation pairs and simple inner residuals. This preserves
     ADR 259 and keeps correlated-IN-with-nested-subqueries deferred.
   - If no conjunct references the membership outer query, the body is uncorrelated and can use the full
     filtering pipeline.
3. **Filter the uncorrelated body plan** with the whole body selection via the standard SELECT filtering steps (a
   small helper mirroring `lower_select`'s filter section — no projection/aggregate/ORDER BY/LIMIT):
   - `pull_up_scalar_subqueries(selection, &mut collected, &body_qualifiers, cte)` with the **body's** qualifiers
     as the scalar outer scope — **not** the union with the membership outer (the uncorrelated body must not let
     a scalar correlate to supplier/nation; q20's scalar correlates to `partsupp`);
   - `inner_plan = self.join_scalar_subplans(inner_plan, collected)?`;
   - `inner_plan = self.lower_where(inner_plan, &combined_body_selection, cte)?` (resolves the nested `IN`
     recursively + applies the residual filter).
4. Return `(inner_plan, inner_key, correlation_pairs)` — the semi-join keys `s_suppkey = ps_suppkey` as today.

Scoping cautions:
- **Uncorrelated only:** q20's body is outer-uncorrelated; keep correlated-IN-with-nested-subqueries a deferred
  sibling.
- **`NOT IN`:** the helper is shared; q20 is plain `IN`. Keep `lower_not_in_subquery_join`'s null-aware
  anti-join desugar intact; if nesting complicates the null guard, scope the generalization to `IN` and defer
  `NOT IN` nesting.
- No new IR. Downstream (nested semi-join 256; deferred two-key scalar 282/260; ADR 284 inner-cartesian keying)
  composes.

## D2 — harness (`crates/toron-tpch`)
1. `lib.rs`: append `p_name` (Utf8) to `part_schema()` + `generate_part()` (`:437`) — only fixture delta.
2. `Q20_DEV_SQL` (official text below), `STRICT_Q20_SQL = Q20_DEV_SQL`, `q20_tables(strict, sf)` over
   **supplier, nation, partsupp, part, lineitem** (no `region`), `run_dev_q20`/`run_strict_q20`, `status_rows`
   entry, matrix row. `facts_for_batch` on every table.
3. `main.rs`: route `"q20"`.

```sql
SELECT s_name, s_address FROM supplier, nation
WHERE s_suppkey IN (
  SELECT ps_suppkey FROM partsupp
  WHERE ps_partkey IN (SELECT p_partkey FROM part WHERE p_name LIKE 'forest%')
    AND ps_availqty > (SELECT 0.5 * SUM(l_quantity) FROM lineitem
      WHERE l_partkey = ps_partkey AND l_suppkey = ps_suppkey
        AND l_shipdate >= DATE '1994-01-01' AND l_shipdate < DATE '1995-01-01')
) AND s_nationkey = n_nationkey AND n_name = 'CANADA'
ORDER BY s_name
```

## Tests
- **Engine-level** (`crates/toron/tests/correlated_scalar_test.rs` or a nearby subquery test):
  - an uncorrelated `x IN (SELECT k FROM t WHERE <nested IN> AND <correlated aggregate scalar>)` binds + executes
    correct rows over matching data. Discriminating: pre-cut rejects at the membership-body classify path
    (revert→fail→restore).
  - a **simple-IN no-regression** control (ADR 256 path) + a **correlated-membership** control (ADR 259 pairs)
    stay green — the generalization must not move them.
- **Gauge** (`toron-tpch/tests/harness.rs`): `q20_executes_in_both_modes` — dev+strict `pass@execute` with a
  digest, or a precise classified wall; inventory/status assertions. q05/q10 explicit-64MB-stack pattern (q20 is
  deep: nested membership + a correlated scalar over lineitem). If it reaches execute, assert `sf=0.01` dev+strict
  pass (keyed/tractable, not a hollow tiny-scale green).

## Risk / blast radius
- The change touches the **shared** IN/membership lowering — ADR 256/258/259 (IN/NOT IN, simple + correlated)
  and any pinned plan digests must stay green. Full `--no-fail-fast` is the net.
- The body filtering recurses the pull-up + `lower_where` — watch the deep-recursion stack class (q20 nests
  membership + a correlated scalar); use the explicit-64MB-stack test pattern from the start.
- Measure-first: if the predicted Int32-vs-Float/Decimal wall (or any other) remains, name it ADR 286 — do not
  let q20 pass only at tiny scale via a cartesian.
