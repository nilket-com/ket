# ADR 301 — Implementation plan: tpch.q09 reachability

Pairs with `plans/adr/0301_tpch_q09.md`. Harness-only (`toron-tpch`) expected; no `crates/toron` engine change
unless the verify-first run measures a real wall (then → ADR 302). Anchors are current-tree.

## Phase 0 — verify-first probe (likely green; the subtraction is the risk)
Wire the minimum and **measure the real first wall**:
```
target/debug/toron-tpch run --query q09 --mode dev   --sf 0.01 --allow-blocked
target/debug/toron-tpch run --query q09 --mode strict --sf 0.01 --allow-blocked
```
Expected `pass@execute` (LIKE via the Arrow kernel; the composite partsupp key via q02; derived body via 294;
EXTRACT/ORDER-BY landed). The genuinely-new risk is the **`(Decimal*Decimal) − (Decimal*Decimal)` profit
subtraction** (two products, scale 4, possibly different precision — a potential arithmetic-alignment gap distinct
from 283/286). Record the raw reason verbatim → ADR 302 if it walls. Add a blocker classifier only for a narrow,
recognizable wall; otherwise keep the measured row as `fail(unrecognized@phase)` and document the raw error. **Also
record whether the result is empty at sf=0.01** (for the future oracle). No broad classifier; no rewrite; no probe
code left behind.

## D1 — fixtures: none new; `q09_tables` assembled directly
`fn q09_tables(strict: bool, scale_factor: f64) -> Vec<HarnessTable>` = build **exactly** `part`, `supplier`,
`lineitem`, `partsupp`, `orders`, `nation` from the existing per-table builders (`generate_part`,
`generate_supplier`, `generate_{dev,strict}_lineitem`, `generate_partsupp`, `generate_orders`, `generate_nation`)
and `facts_for_batch` on each. **Do not** filter `q08_tables` (it has `customer`/`region`, lacks `partsupp`). No
new columns.

## D2 — wiring — `lib.rs` + `main.rs`
- `Q9_DEV_SQL` (official Q9, `:1`→`'green'`, no LIMIT, `ORDER BY nation, o_year DESC`); `STRICT_Q9_SQL =
  Q9_DEV_SQL`.
- `q09_tables` (D1); `run_dev_q09`/`run_strict_q09` via `run_query_with_tables("q09", …, q09_tables(strict, sf))`.
- `status_rows()` — add `"q09"`; matrix row renders. `main.rs` — route `"q09"|"q9"` (dev/strict).

## Tests — `crates/toron-tpch/tests/harness.rs`
- `q09_executes_in_both_modes` (or the measured-wall assertion if it doesn't reach execute): dev+strict at
  `sf=0.01`, `Status::Pass` / `Phase::Execute` + digest. Explicit-64MB-stack thread (q09 is a deep 6-table derived
  + grouped aggregate).
- **Keyed-at-default-scale evidence** — q09 must be keyed at `sf=0.01` (6-table incl. the partsupp composite key;
  the q14/q17 cartesian lesson). A cartesian is an honest red.
- **No-regression** — existing reach (q01-08/10/12/14/17/20) + correctness cells stay green (full `-p toron-tpch`);
  no fixture change.
- If q09 walls, assert the measured phase/status/reason (not a green); use a new blocker reason only if the raw
  error is narrow enough to classify honestly. The results doc names ADR 302 either way.

## Risk / blast radius
- Harness-only (expected). No fixture change → low blast radius; the full `-p toron-tpch` suite + the two matrices
  are the net.
- **The profit subtraction is the genuinely-new risk** — two Decimal products, same scale, possibly different
  precision; if it walls, that's a real engine cut (ADR 302), distinct from 283/286 comparison alignment.
- **Verify at default scale** — a tiny-scale-only pass (or a cartesian) over the 6-table join is not evidence.
- **Six relations, assembled directly** (not a filtered `q08_tables`).
- If q09 walls, honest red + name ADR 302; no broad classifier, no rewrite.
