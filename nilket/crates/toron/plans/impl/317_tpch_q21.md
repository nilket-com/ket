# ADR 317 — Implementation plan: tpch.q21 reachability

Pairs with `plans/adr/317_tpch_q21.md`. Harness-only (`toron-tpch`); no `crates/toron` engine change in this cut.
Verify-first, measure-first. The **last reach probe** — closes the failure atlas.

## Phase 0 — verify-first probe (measure; do not predict)
Wire the minimum and **measure both modes**:
```
scripts/cargo-cgroup run -p toron-tpch -- run --query q21 --mode dev --sf 0.01 --allow-blocked
scripts/cargo-cgroup run -p toron-tpch -- run --query q21 --mode strict --sf 0.01 --allow-blocked
```
**Record both raw rows verbatim.** Expected candidates, by phase:
- `@bind` `o_orderstatus` not-found (the fixture gap) — or
- `@plan`/`@bind` on the correlated EXISTS/NOT-EXISTS `<>` cross-side correlation (decorrelation maps equi-pairs
  only; `l2.l_suppkey <> l1.l_suppkey` won't decorrelate).
If a keyless-cross/family reject appears, **confirm the cause** before recording family evidence. Don't leave probe
code behind.

## D1 — fixtures: none up front (`o_orderstatus` is the contingency)
`fn q21_tables(strict, sf)` over `supplier` (`generate_supplier`) + `lineitem` (`generate_{dev,strict}_lineitem`) +
`orders` (`generate_orders`) + `nation` (`generate_nation`); `facts_for_batch` each. **Contingency:** only if
Phase-0 shows `o_orderstatus` not-found `@bind` masking the correlated-`<>` wall — append `o_orderstatus` (Utf8) to
`orders_schema` + populate from `OrderGenerator.o_orderstatus`; then full `-p toron-tpch` + both matrices + orders
goldens to prove q03/q04/q05/q10/q12/q13/q22 unmoved (postcard-preimage caution). Re-measure after.

## D2 — wiring — `lib.rs` + `main.rs`
- `Q21_DEV_SQL` (official q21: `supplier, lineitem l1, orders, nation`; `s_suppkey = l1.l_suppkey AND o_orderkey =
  l1.l_orderkey AND o_orderstatus = 'F' AND l1.l_receiptdate > l1.l_commitdate`; `EXISTS (… l2.l_orderkey =
  l1.l_orderkey AND l2.l_suppkey <> l1.l_suppkey)`; `NOT EXISTS (… l3 … AND l3.l_receiptdate > l3.l_commitdate)`;
  `s_nationkey = n_nationkey AND n_name = 'SAUDI ARABIA'`; `GROUP BY s_name`; `COUNT(*) AS numwait`; `ORDER BY
  numwait DESC, s_name`; `LIMIT 100`); `STRICT_Q21_SQL = Q21_DEV_SQL`.
- `q21_tables`; `run_dev_q21`/`run_strict_q21` via `run_query_with_tables("q21", …, q21_tables(strict, sf))`.
- `status_rows()` — add `"q21"`; matrix row. `main.rs` — route `"q21"` (dev/strict).

## D3 — classifier (match the measured wall, confirm cause)
- Correlated-`<>` reject → add a **specific** reason only if the raw message supports one (narrow, before the
  generic buckets, no overclassification) + a unit test; else `fail(unrecognized@phase)` + document raw. Do not
  reuse a family reason (`unsupported_cross_join`, EXISTS-shape) unless the cause is confirmed identical.
- `o_orderstatus` gap → not a classifier (the D1 contingency).

## Tests — `crates/toron-tpch/tests/harness.rs`
- `q21_blocks_on_<measured-wall>` (the measured shape): dev + strict at sf=0.01 assert the measured
  `Status`/`Phase`/`reason`. 64MB-stack thread (q21 is the deepest query — 4-table join + two correlated
  subqueries + a triple self-join).
- If q21 unexpectedly reaches execute, a keyed/tractability check at sf=0.01 (the triple self-join must not be a
  fake-green cartesian); a tiny-scale-only pass is not a green reach cell.
- **No-regression** — prior reach rows + the 17 correctness cells stay unchanged; no fixture change unless the
  contingency fired.

## Phase 3 — record the diagnostic finding + the completed atlas
Results doc records: which wall fired first (`o_orderstatus` gap vs correlated-`<>` EXISTS/NOT-EXISTS vs other);
the raw reject; the next-ADR direction; and **the completed failure atlas** (q11/q15/q18/q19/q21 families with
their measured reproductions) so the engine sequence can be scoped from one place.
