# ADR 290 — Implementation plan: tpch.q12 reachability

Pairs with `plans/adr/290_tpch_q12.md`. Harness-only (`toron-tpch`) expected; no `crates/toron` engine change
unless the verify-first run measures a real wall (then → ADR 291). Anchors are current-tree.

## Phase 0 — verify fixture assumptions
Confirm the current harness state before changing it:
- `tpchgen::generators::LineItem` exposes `l_shipmode`.
- `orders` already exposes `o_orderkey` and `o_orderpriority`.
- `lineitem` already exposes `l_orderkey`, `l_shipdate`, `l_commitdate`, and `l_receiptdate`.
- `lineitem` does not yet expose `l_shipmode`.

Do not leave probe code behind.

## Phase 1 — fixture (append-only) — `crates/toron-tpch/src/lib.rs`
- Append `l_shipmode` (`DataType::Utf8`, non-nullable) to **both** `dev_lineitem_schema` and
  `strict_lineitem_schema`.
- In `generate_dev_lineitem` and `generate_strict_lineitem`, push `item.l_shipmode.to_string()` and add the
  column to the `RecordBatch` (same shape as ADR 285's `p_name` append).
- Nothing else changes on `lineitem`; `orders` is untouched (`o_orderpriority`/`o_orderkey` already present).
- **Append-only discipline:** the new column must be transparent to every other query. The gate proves existing
  reach + correctness rows don't move.

## Phase 2 — wiring — `lib.rs` + `main.rs`
- `Q12_DEV_SQL` (tpchgen Q12 with `:1`/`:2`/`:3` bound to `'MAIL'`/`'SHIP'`/`DATE '1994-01-01'`, and the upper
  interval bound literalized to `DATE '1995-01-01'`); `STRICT_Q12_SQL = Q12_DEV_SQL`.
- `fn q12_tables(strict: bool, scale_factor: f64) -> Vec<HarnessTable>` over `orders` + `lineitem` (mirror
  `q14_tables`/`q17_tables`/`q05_tables`); `facts_for_batch` on both.
- `run_dev_q12` / `run_strict_q12` via `run_query_with_tables("q12", …, q12_tables(strict, sf))`.
- `status_rows()` — add `"q12"` to the implemented list; matrix row renders.
- `main.rs` — route `"q12"` in `run_command` (dev/strict).

## Phase 3 — verify-first measurement
Measure the real row before declaring anything green:
```
target/debug/toron-tpch run --query q12 --mode dev   --sf 0.01 --allow-blocked
target/debug/toron-tpch run --query q12 --mode strict --sf 0.01 --allow-blocked
```
Grounded expectation: `pass@execute` (all primitives landed — `InList`, CASE-in-SUM, Date32 column-to-column
comparison, comma join). If instead it blocks/fails, record the **precise** phase + reason verbatim — that names
ADR 291; do **not** add a broad classifier or reshape the query to dodge it.

## Tests — `crates/toron-tpch/tests/harness.rs`
- `q12_executes_in_both_modes` (or the precise measured-wall assertion if it doesn't reach execute): dev+strict at
  `sf=0.01`, `Status::Pass` / `Phase::Execute` with a digest. Use the explicit-64MB-stack thread pattern if the
  query is deep (comma join + grouped CASE aggregates).
- **Keyed-at-default-scale evidence** — assert q12 runs at `sf=0.01` (not just a tiny scale); the comma join must
  be keyed (the q14/q17 cartesian lesson). If feasible, a `q12_runs_keyed_at_default_scale`-style check (like q14).
- **Append-only proof** — the existing reach board (q01-06/10/14/17/20) and correctness cells stay green with the
  new `l_shipmode` column (the full `-p toron-tpch` suite, including the correctness tests, is the net).

## Seal gate (via `scripts/cargo-cgroup`, after `fmt`)
```
scripts/cargo-cgroup fmt
scripts/cargo-cgroup fmt -- --check
scripts/cargo-cgroup check -p toron-tpch --all-targets
scripts/cargo-cgroup test -p toron-tpch
scripts/cargo-cgroup run -p toron-tpch -- run --query q12 --mode dev --sf 0.01
scripts/cargo-cgroup run -p toron-tpch -- run --query q12 --mode strict --sf 0.01
scripts/cargo-cgroup run -p toron-tpch -- matrix
scripts/cargo-cgroup run -p toron-tpch -- correctness-matrix
git diff --check
```
Those two live q12 runs are part of the gate, not optional prose. If they produce a red row instead of
`pass@execute`, the results doc records that precise wall.

## Risk / blast radius
- Harness-only (expected). The risk is a **non-append-only** fixture change moving another row — the full
  `-p toron-tpch` suite + the two matrices are the net.
- **Verify at default scale** — a tiny-scale-only pass over a cartesian comma join is not evidence (q14/q17
  lesson). Confirm the join is keyed at `sf=0.01`.
- If q12 walls, **do not** add a broad classifier or rewrite the query — record the honest red and name ADR 291.
- Don't pin/guess the count-aggregate output type — defer to a future q12 correctness oracle.
