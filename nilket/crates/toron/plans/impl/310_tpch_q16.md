# ADR 310 — Implementation plan: tpch.q16 reachability

Pairs with `plans/adr/310_tpch_q16.md`. Harness-only (`toron-tpch`); no `crates/toron` engine change expected, no
fixture change. Verify-first.

## Phase 0 — verify-first probe
Wire the minimum and **measure**:
```
target/debug/toron-tpch run --query q16 --mode dev   --sf 0.01 --allow-blocked
target/debug/toron-tpch run --query q16 --mode strict --sf 0.01 --allow-blocked
```
Expected `pass@execute` in both modes based on the grounded substrate, but record the raw error verbatim if it
walls (that determines the classifier). Confirm keyed execution; a partsupp x part cartesian would be materially
slower than the equi-join. Do not leave probe code behind.

## D1 — fixtures: none new
`fn q16_tables(strict, sf)` over `part` (`generate_part`) + `partsupp` (`generate_partsupp`) + `supplier`
(`generate_supplier`); `facts_for_batch` each. No new columns (`p_brand`/`p_type`/`p_size`/`ps_partkey`/
`ps_suppkey`/`s_suppkey`/`s_comment` all exist).

## D2 — wiring — `lib.rs` + `main.rs`
- `Q16_DEV_SQL` (official q16: comma-join `partsupp, part` on `p_partkey = ps_partkey`; `p_brand <> 'Brand#45'`;
  `p_type NOT LIKE 'MEDIUM POLISHED%'`; `p_size IN (49,14,23,45,19,3,36,9)`; `ps_suppkey NOT IN (SELECT s_suppkey
  FROM supplier WHERE s_comment LIKE '%Customer%Complaints%')`; `GROUP BY p_brand, p_type, p_size`; `ORDER BY
  supplier_cnt DESC, p_brand, p_type, p_size`); `STRICT_Q16_SQL = Q16_DEV_SQL`.
- `q16_tables`; `run_dev_q16`/`run_strict_q16` via `run_query_with_tables("q16", …, q16_tables(strict, sf))`.
- `status_rows()` — add `"q16"`; matrix row. `main.rs` — route `"q16"` (dev/strict).

## D3 — classifier (only if it walls)
If Phase-0 shows a wall, add a **specific** telemetry reason matching the raw reject (narrow, before the generic
buckets, no overclassification) + a unit test. Expected: not needed (likely green).

## Tests — `crates/toron-tpch/tests/harness.rs`
- `q16_executes_in_both_modes_at_default_scale` (or the measured-wall assertion): dev+strict at sf=0.01,
  `Status::Pass` / `Phase::Execute` + digest. 64MB-stack thread if deep.
- **Keyed-at-default-scale** — q16's partsupp ⋈ part must be keyed at sf=0.01 (equi-join; not a cartesian). Keep
  any timing threshold loose and diagnostic; this is a tractability tripwire, not a CPU benchmark.
- **No-regression** — existing reach (q01-10/12/13/14/17/20/22) + the 16 correctness cells stay green; no fixture
  change.

## Phase 3 — confirm + record for the future oracle
- `pass@execute` → flip the q16 harness row to green; reach → 17. Confirm keyed.
- Record (results doc): whether the output is **non-empty** at sf=0.01, and whether the `NOT IN` excludes ≥1
  supplier live (`%Customer%Complaints%` matches some `s_comment`) — needed for the future q16 correctness oracle
  (else the anti-semijoin is synthetic-only there).
- A wall → record the precise reason (next ADR); no broad classifier.

## Results doc
`crates/toron/plans/impl/310_tpch_q16_results.md`: the measured q16 dev+strict rows (keyed); non-emptiness +

## Risk / blast radius
- Harness-only (expected). No fixture change → low blast radius; the full `-p toron-tpch` suite + matrices are the
  net.
- **Verify keyed at default scale** — not a cartesian.
- **If it walls** — precise classifier, defer the engine cut; don't pre-solve COUNT(DISTINCT) / the null-aware
  anti-semijoin.
- q16 is mode-agnostic at the output surface (no decimals projected) — dev and strict are expected to match, but
  the implementation records the measured digests rather than assuming equality.
