# Implementation Plan — ADR 277: tpch.q05 reachability attempt

## Summary
A harness reachability attempt (not an engine cut): append `l_suppkey` to the `lineitem` fixtures, add
`supplier` + `region`, wire the tpchgen-exact q05 SQL through the multi-table harness (q05 is its first 6-table
user), run dev + strict, and record the measured first wall. Scope: `crates/toron-tpch`. The likely wall is the
cyclic/multi-key join graph (the supplier edge's extra equalities) — measured, not asserted.

## Phase 0 — verify the board
`matrix` → q01/q03/q06/q10/q14 `pass@execute`, q05 `not_run`; `correctness-matrix` → q06 + q01 `pass@compare`.

## Phase 1 — fixtures (`lib.rs`)
- **`l_suppkey` append.** Add `Field::new("l_suppkey", DataType::Int64, false)` to the END of
  `dev_lineitem_schema` and `strict_lineitem_schema`, and push `item.l_suppkey` in `generate_dev_lineitem` /
  `generate_strict_lineitem`. Append-only: q01/q03/q06/q10/q14 reference no new column, so their outputs +
  digests are unchanged (confirm in Phase 4).
- **`supplier`**: `supplier_schema` (`s_suppkey` Int64, `s_nationkey` Int64), `supplier_descriptor`
  (`TableObjectId::new([19; 16])` — verify unused), `generate_supplier(sf)` from
  `tpchgen::generators::SupplierGenerator` (no decimals → identical dev/strict; q05 needs only the two keys).
- **`region`**: `region_schema` (`r_regionkey` Int64, `r_name` Utf8), `region_descriptor`
  (`TableObjectId::new([21; 16])` — verify unused), `generate_region(sf)` from `RegionGenerator` (5 rows;
  `r_name.to_string()`).
- **Reuse `nation`** as-is (`n_nationkey`, `n_name`, `n_regionkey` — ADR 274). customer/orders unchanged.

## Phase 2 — q05 SQL (`lib.rs`)
`Q5_DEV_SQL` / `STRICT_Q5_SQL` = tpchgen Q5 with `:1` → `'ASIA'`, `:2` → `'1994-01-01'`, interval upper bound →
`DATE '1995-01-01'`, `ORDER BY revenue DESC` (no LIMIT). Same text both modes.

## Phase 3 — wiring (`lib.rs` + `main.rs`)
- `q05_tables(strict, scale_factor)` = `q10_tables(strict, sf)` (lineitem `TableId(1)`, customer `2`, orders
  `3`, nation `4`) **plus** `supplier` `TableId(5)` and `region` `TableId(6)` — reusing the q10 builder, the
  same way `q10_tables` extended `q03_tables`.
- `run_dev_q05` / `run_strict_q05` via `run_query_with_tables`. CLI: `run --query q05 --mode dev|strict`
  (mirror the q10 arm). `status_rows` → q05 `implemented`.

## Phase 4 — measure (+ classifier if a blocker appears)
- Run `run --query q05 --mode dev|strict --allow-blocked` + `matrix`; record the measured row from the **full**
  q05 attempt. If strict/dev walls on the join graph, read the actual error and add a precise recognized
  blocker (e.g. an `unsupported_join_graph`-style reason matching the actual message), placed so it doesn't
  fall to a generic bucket; if it walls elsewhere, classify *that* (or honest `fail`). Don't force a row.
- Re-run the existing reachability suite + q06/q01 correctness checks → confirm q01/q03/q06/q10/q14 stay green
  and q06/q01 stay `pass@compare` after the `l_suppkey` append.

## Phase 5 — tests (`tests/harness.rs`)
- A q05 test on the **explicit large-stack thread** (`std::thread::Builder::stack_size(64 MB)` + a
  current-thread runtime — the q10 pattern; a bare `#[tokio::test]` overflows on a 6-table future): asserts the
  measured row in both modes (pass `@execute` + digest, or `blocked` at its phase with the precise reason) and
  q05 `implemented` in `status`.
- If q05 passes, add a dev default-scale (`sf=0.01`) test on the same large-stack wrapper, analogous to q03/q14:
  a keyed six-table plan should complete, while a missed join edge/cartesian shape should not be hidden by the
  tiny reachability scale. If q05 blocks before execute, skip this guard and let the blocker row stand.
- If a join-graph classifier lands, a `reason_for_error` unit assertion pinning the exact message → reason.
- q01/q03/q06/q10/q14 reachability + the q06/q01 correctness tests stay green (the append is transparent).

## Risk notes
- **Don't move q01/q03/q06/q10/q14.** `l_suppkey` is appended; existing queries + the correctness cells stay
  byte-stable (verify, don't assume).
- **Measure, don't assert the wall.** The multi-key join graph is the *expected* stressor; the impl records the
  actual single-node reachability outcome (6th green cell, or a precise blocker naming the next ADR).
- **No engine feature.** strict stays `Decimal128`; a measured wall is the honest deliverable.
- **6-table needs the explicit-stack test** (recurs from q10).
