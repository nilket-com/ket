# ADR 316 — Implementation plan: tpch.q19 reachability

Pairs with `plans/adr/0316_tpch_q19.md`. Harness-only (`toron-tpch`); no `crates/toron` engine change in this cut.
Verify-first, measure-first. Completes (with q21) the reach map → the failure atlas.

## Phase 0 — verify-first probe (measure; do not predict)
Wire the minimum and **measure both modes**:
```
target/debug/toron-tpch run --query q19 --mode dev    --sf 0.01 --allow-blocked
target/debug/toron-tpch run --query q19 --mode strict --sf 0.01 --allow-blocked
```
**Record both raw rows verbatim.** Expected candidates, by phase:
- `@bind` `l_shipinstruct` not-found (the fixture gap) — or
- `@bind` keyless-cross / broadcast-build-side (the disjunctive predicate hiding `p_partkey = l_partkey`).
If the keyless-cross fires, **confirm the cause is the disjunction** (the equi-key only appears inside OR-branches)
before treating it as q15-family evidence. Don't leave probe code behind.

## D1 — fixtures: none up front (`l_shipinstruct` is the contingency)
`fn q19_tables(strict, sf)` over `lineitem` (`generate_{dev,strict}_lineitem`) + `part` (`generate_part`);
`facts_for_batch` each. **Contingency:** only if Phase-0 shows `l_shipinstruct` not-found `@bind` masking the
disjunctive wall — append `l_shipinstruct` (Utf8) to the lineitem schema + populate from
`LineItemGenerator.l_shipinstruct`; then full `-p toron-tpch` + both matrices + lineitem goldens to prove the many
lineitem-backed rows (q01/q03/q05/q06/q07/q09/q12/q14/q18 …) unmoved (postcard-preimage caution). Re-measure after.

## D2 — wiring — `lib.rs` + `main.rs`
- `Q19_DEV_SQL` (official q19: `lineitem, part`; the 3 OR-branches each `p_partkey = l_partkey AND p_brand = … AND
  p_container IN (…) AND l_quantity >= … AND l_quantity <= … AND p_size BETWEEN … AND l_shipmode IN ('AIR','AIR
  REG') AND l_shipinstruct = 'DELIVER IN PERSON'`; `SUM(l_extendedprice * (1 - l_discount)) AS revenue`);
  `STRICT_Q19_SQL = Q19_DEV_SQL`.
- `q19_tables`; `run_dev_q19`/`run_strict_q19` via `run_query_with_tables("q19", …, q19_tables(strict, sf))`.
- `status_rows()` — add `"q19"`; matrix row. `main.rs` — route `"q19"` (dev/strict).

## D3 — classifier (match the measured wall, confirm cause)
- Disjunctive keyless-cross → if it's q15's `unsupported_cross_join` (broadcast-build-side), it already classifies;
  **record the disjunctive cause + the q15 match** in the results doc (family evidence) only after confirming the
  equi-key is buried in OR-branches (not some other keyless path).
- `l_shipinstruct` gap → not a classifier (a fixture fix); the D1 contingency.
- A different reject → a precise new reason only if the raw message supports one; else `fail(unrecognized@phase)` +
  document raw.

## Tests — `crates/toron-tpch/tests/harness.rs`
- `q19_blocks_on_<measured-wall>` (the measured shape): dev + strict at sf=0.01 assert the measured
  `Status`/`Phase`/`reason`. 64MB-stack thread if deep.
- If q19 unexpectedly passes, the test runs at `sf=0.01` and records tractability/keyed evidence; a tiny-scale-only
  pass is not a green reach cell.
- **No-regression** — existing reach (q01-11/12/13/14/16/17/20/22) + the 17 correctness cells stay green; no
  fixture change (unless the contingency fired — then the lineitem-backed rows are the net).

## Phase 3 — record the diagnostic finding (the atlas row)
Results doc records: which wall fired first (`l_shipinstruct` gap vs disjunctive keyless-cross); the raw reject;
**whether it matches q15's `unsupported_cross_join` and that the cause is the disjunction** (family evidence
yes/no); the next-ADR direction (disjunction-to-keyed-join factoring, possibly batched with q15's composite cut as
one keyless-cross-family ADR).

## Seal gate (via `scripts/cargo-cgroup`, after `fmt`)
```
scripts/cargo-cgroup fmt
scripts/cargo-cgroup fmt -- --check
scripts/cargo-cgroup check -p toron-tpch --all-targets
scripts/cargo-cgroup test -p toron-tpch
scripts/cargo-cgroup run -p toron-tpch -- run --query q19 --mode dev --sf 0.01 --allow-blocked
scripts/cargo-cgroup run -p toron-tpch -- run --query q19 --mode strict --sf 0.01 --allow-blocked
scripts/cargo-cgroup run -p toron-tpch -- matrix
scripts/cargo-cgroup run -p toron-tpch -- correctness-matrix
git diff --check
```
The two live q19 runs are part of the gate — they produce the measured rows. If the measured row is an honest
`fail(unrecognized@phase)`, do not invent a blocker just to make `--allow-blocked` exit green; pin the nonzero
outcome in the harness test/results doc and keep the rest of the gate green with an explicit expected-failure shell
wrapper for the live commands.

## Results doc
`crates/toron/plans/impl/0316_tpch_q19_results.md`: the measured q19 dev+strict rows; the first wall + raw reject;
the q15-family finding (matches `unsupported_cross_join` + disjunctive cause confirmed, yes/no); if q19 greens,
default-scale tractability/keyed evidence; the next-ADR direction; confirmation prior reach + correctness rows
unchanged.

## Risk / blast radius
- Harness-only (expected). No fixture change in the expected path → low blast radius; the full `-p toron-tpch`
  suite + matrices are the net.
- **Contingency fixture add** (`l_shipinstruct`, if forced) touches the shared lineitem fixture — full suite +
  goldens mandatory then.
- **Don't pre-solve** the disjunctive predicate — measure + defer to its own engine ADR.
- **Confirm the cause** before recording q15-family evidence — a keyless-cross can have multiple causes.
