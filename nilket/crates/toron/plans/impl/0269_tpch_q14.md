# Implementation Plan — ADR 269: tpch.q14 (first measured row)

## Summary
A harness cut, not an engine cut. Generalize the single-table `run_query` to a multi-table helper, add
`lineitem`+`part` fixtures (dev `Float64` / strict `Decimal128`) with seeded optimizer facts, wire the
official-shaped q14 SQL through CLI / status / matrix, run it both modes, and record the measured first wall as
a **specific** recognized blocker. No wall is implemented here.

## Phase 0 — verify the board
`scripts/cargo-cgroup run -p toron-tpch -- matrix` → confirm `q14 dev=not_run strict=not_run`, q01/q06 green.

## Phase 1 — multi-table harness (`crates/toron-tpch/src/lib.rs`)
- `run_query` (`:290`) registers one descriptor as `TableId(1)` + one batch. Add:
  ```rust
  struct HarnessTable { id: TableId, descriptor: TableSchemaDescriptor, batch: RecordBatch }
  async fn run_query_with_tables(query_id, mode, scale_factor, sql, tables: Vec<HarnessTable>) -> Attempt
  ```
  Same Load→Plan→Bind→Execute→digest staging as `run_query`, but registers **all** tables (and seeds all
  batches into `HarnessScan`) before plan. Keep `run_query` as a one-table wrapper delegating to it, so
  q01/q06 behavior and digest assertions remain unchanged.

## Phase 2 — q14 SQL (`lib.rs`)
- `Q14_DEV_SQL` / `STRICT_Q14_SQL` (comma-join, literal dates — the ADR's quoted shape, verbatim). Same text
  in both modes; only the fixture column types differ (the q01/q06 dev/strict discipline). Do **not** rewrite
  the comma-join, CASE, or `/`.

## Phase 3 — fixtures (`lib.rs`)
- `lineitem`: add `l_partkey: Int64` to the dev and strict schemas + generators (`generate_dev_lineitem` /
  `generate_strict_lineitem` and their `*_schema`/`*_descriptor`). **Append** the key so existing q01/q06
  column positions and the q06 digest don't move (re-pin only if unavoidable, in this cut).
- `part`: new `(p_partkey Int64, p_type Utf8)` fixture, dev and strict identical (no decimals). Rows: one
  `p_type LIKE 'PROMO%'` and one not, partkeys matching the lineitem rows; a September-1995 `l_shipdate` so
  the date window admits them (the mock scan ignores pushed predicates, so the window is illustrative — keep
  values honest anyway).
- **Optimizer facts, not descriptor fields.** `TableSchemaDescriptor` does not carry row counts. After
  registering each descriptor, seed the `MockCatalog` with `TableOptimizerFacts` for the harness tables
  (`seed_optimizer_facts_for_table_id` is the direct path). Give `part` and `lineitem` realistic
  `row_upper_bound` / byte facts so join planning sees a real, tiny build side — the measured wall must be the
  genuine wall, not an artifact of an underspecified fixture.

## Phase 4 — CLI / inventory / matrix (`lib.rs` + CLI)
- `run_dev_q14` / `run_strict_q14` (build the two `HarnessTable`s, call `run_query_with_tables`).
- CLI dispatch: `run --query q14 --mode dev|strict` routes to them (mirror the q01/q06 arms).
- `status_rows`: q14 → `implemented` (it already exists in `ALL_QUERY_IDS`). `status` stays static capability;
  the measured row lives only in the JSONL/matrix.

## Phase 5 — measure + classify (`telemetry.rs`)
- Run `run --query q14 --mode strict --allow-blocked` and read the actual reason. **Expected (probe):** the
  comma-join cross-join — map `"CROSS JOIN requires a broadcast-eligible build side"` → a new
  `unsupported_cross_join`, added to `RECOGNIZED_BLOCKERS` + the classifier (kept specific to the cross-join
  message, per ADR 262's precise-match discipline).
- **If the seeded-facts fixture admits the cross-join** (tiny broadcast-eligible `part`) and q14 walls later,
  classify *that* reason instead (e.g. `unsupported_decimal_case` for `"CASE result branches cannot be
  unified: Decimal128(...) and Int32"`). Add exactly the reason measured — do not pre-add speculative buckets.

## Phase 6 — tests (`crates/toron-tpch/tests/`)
- `harness.rs`: q14 dev + strict each record the measured phase/reason (assert the specific recognized reason,
  not a generic surface); q14 appears `implemented` in `status`; `matrix_from_log` renders q14's
  `reason@phase`. Mirror the `q01`/`q06` test shapes.
- Keep the verify-first probe as a grounding regression (`q14_probe.rs` or folded into `decimal_probe.rs`):
  the full-q14 bind on a 2-table strict fixture without optimizer facts asserts the no-facts comma-join wall.
  The harness tests separately assert the actual q14 row measured with seeded optimizer facts.
- Architecture guard (if the multi-table runner lands): the helper registers every descriptor before
  plan/bind, and q01/q06 keep the one-table path.

Acceptance: q14 moves `not_run` → a measured, recognized, specific row both modes; q01/q06 unchanged; the measured
reason is allowlisted with a precise classifier. **If q14 blocks, do not implement the blocker** — record the
measured phase/reason in the results doc and let it name ADR 270.

## Risk notes
- **Don't move q01/q06.** Appending `l_partkey` must not reorder existing columns / shift the q06 digest.
- **Classify what you measure.** The expected `unsupported_cross_join` is from a descriptor-only fixture
  without optimizer facts; the impl records the real wall against seeded-facts fixtures — the honest row is the
  deliverable.
- **No engine feature** sneaks in to "help" q14 pass; strict stays `Decimal128`.
